## 1. 背景与目标

AI 驱动的端到端企业级测试平台需要承载需求解析、测试资产生产、接口/UI/E2E 自动执行、失败诊断、报告分析和企业集成等能力。上述能力都依赖稳定的平台基础底座：清晰的组织边界、可靠的数据隔离、可配置的项目与应用上下文、可审计的权限与操作记录。

WP1 的目标是在 MVP 阶段优先建设企业级测试平台的控制面基础能力，保证后续测试资产、执行任务、模型策略、集成配置、报告数据都能归属于正确的租户、部门、项目、应用和环境，并在权限控制和审计要求下安全运行。

### 1.1 业务目标

- 支持平台以多租户、多部门、多项目、多应用方式管理企业测试资产。
- 建立用户、角色、权限的统一管理能力，为后续资产生产、执行、审批、配置和报告模块复用。
- 建立环境配置能力，支持按项目和应用维护接口、UI、鉴权、变量等测试运行基础信息。
- 建立操作审计能力，满足企业内部追踪、合规、问题定位和安全复盘需求。
- 为后续 WP 的需求资产、用例资产、执行调度、AI Agent、模型策略和企业集成提供统一上下文。

### 1.2 产品目标

- 管理员可以完成租户、部门、用户、项目、应用、环境、角色和权限的基础配置。
- 项目负责人可以管理本项目下的应用、成员、环境和基础配置。
- 普通成员只能访问被授权的项目、应用和环境数据。
- 所有关键写操作、权限变更、登录行为和配置变更都有可查询审计日志。
- MVP 阶段先保证核心链路闭环，保留组织同步、复杂审批、细粒度字段权限等后续扩展点。

### 1.3 成功指标

| 指标 | MVP 目标 |
|---|---|
| 基础配置闭环 | 新租户从创建到项目、应用、环境、成员配置可完整完成 |
| 权限准确性 | 未授权用户无法访问项目、应用、环境和审计数据 |
| 审计覆盖率 | P0 关键操作 100% 记录审计日志 |
| 管理效率 | 管理员可在 10 分钟内完成一个租户的基础初始化 |
| 扩展适配 | 后续测试资产、执行任务、模型策略可复用租户/项目/应用/环境上下文 |

## 2. 范围与非范围

### 2.1 本期范围

- 租户管理：创建、编辑、启停、查看租户基础信息。
- 部门管理：维护部门树、部门负责人、部门成员关系。
- 用户管理：创建/邀请用户、启停用户、分配部门、分配角色、查看用户项目权限。
- 项目管理：创建项目、维护项目基础信息、项目成员、项目状态。
- 应用管理：在项目下维护被测应用，支持应用类型、负责人和基础访问配置。
- 环境管理：在项目/应用下维护测试环境，支持环境变量、服务地址、鉴权配置和启停。
- 角色权限：提供平台级、租户级、项目级角色；支持角色授权与用户绑定。
- 操作审计：记录登录、配置、权限、成员、环境等关键操作，支持查询和详情查看。
- Web 管理后台：提供基础管理页面和关键表单交互。

### 2.2 本期非范围

- 不建设完整 SSO/LDAP/企业微信/钉钉/飞书组织同步，仅预留外部身份 ID 和集成字段。
- 不建设复杂审批流，例如项目创建审批、权限申请审批、环境变更审批。
- 不建设测试资产库、用例生成、脚本生成、执行调度和报告看板的完整能力。
- 不建设模型路由、模型密钥管理和 AI Agent 工作流，仅为后续按租户/项目/应用配置策略预留字段。
- 不建设跨租户数据分析和集团级合并报表。
- 不建设计费、资源配额、套餐管理等商业化能力。
- 不建设字段级权限、数据脱敏策略编辑器和复杂 ABAC 策略。

### 2.3 依赖与假设

- 平台默认存在一个超级管理员入口，用于初始化租户和平台级管理员。
- MVP 阶段以 Web 管理后台作为主要使用入口。
- 后端服务需要提供统一租户上下文与权限校验能力，供后续模块复用。
- 审计日志应由服务端统一生成，前端不直接决定审计是否记录。

## 3. 用户角色与权限

### 3.1 角色定义

| 角色 | 角色定位 | 典型用户 | 权限范围 |
|---|---|---|---|
| 平台超级管理员 | 平台初始化与全局治理 | 平台运维、平台负责人 | 全平台租户、系统配置、审计查看 |
| 租户管理员 | 单租户组织与权限管理 | 企业测试平台管理员 | 本租户部门、用户、角色、项目、审计 |
| 部门负责人 | 部门成员和部门项目协同 | QA 负责人、研发负责人 | 本部门信息、成员查看、部门项目查看 |
| 项目负责人 | 项目交付和质量资产负责人 | 测试经理、项目经理 | 本项目成员、应用、环境、基础配置 |
| 应用负责人 | 单应用测试配置负责人 | 应用研发负责人、应用 QA | 本应用配置、环境配置、成员查看 |
| 测试工程师 | 资产生产与执行使用者 | QA | 授权项目/应用下的查看与使用权限 |
| 研发工程师 | 协作查看与问题定位 | RD | 授权项目/应用下的查看、环境查看 |
| 只读审计员 | 合规审计和问题复盘 | 内控、安全、审计人员 | 授权范围内审计日志只读 |

### 3.2 权限模型

MVP 采用 RBAC 为主的权限模型，并按资源归属限制数据范围。

| 权限层级 | 说明 | 示例 |
|---|---|---|
| 平台级 | 跨租户的系统管理权限 | 创建租户、查看全局审计 |
| 租户级 | 租户内组织、用户、角色和项目管理权限 | 创建部门、邀请用户、创建项目 |
| 项目级 | 单项目内成员、应用、环境和配置权限 | 添加项目成员、创建应用 |
| 应用级 | 单应用配置与环境使用权限 | 编辑应用信息、查看应用环境 |
| 环境级 | 特定环境的查看、编辑和使用权限 | 编辑测试环境变量、使用预发环境执行 |

### 3.3 MVP 预置角色

| 预置角色 | 层级 | 核心权限 |
|---|---|---|
| SuperAdmin | 平台级 | 租户全管理、平台审计、系统初始化 |
| TenantAdmin | 租户级 | 部门、用户、角色、项目、租户审计管理 |
| ProjectOwner | 项目级 | 项目配置、项目成员、应用、环境管理 |
| AppOwner | 应用级 | 应用信息、应用环境管理 |
| Tester | 项目级 | 查看项目、查看应用、使用环境 |
| Developer | 项目级 | 查看项目、查看应用、查看环境 |
| Auditor | 租户级/项目级 | 查看授权范围内审计日志 |

## 4. 核心业务对象

### 4.1 租户 Tenant

租户是平台数据隔离的最高业务边界，代表一个企业、事业部或独立组织。

| 字段 | 说明 |
|---|---|
| 租户 ID | 系统唯一标识 |
| 租户名称 | 展示名称，租户内唯一 |
| 租户编码 | 系统识别编码，全局唯一 |
| 状态 | 启用、停用 |
| 管理员 | 一个或多个租户管理员 |
| 联系信息 | 联系人、邮箱、手机号 |
| 数据保留策略 | MVP 可先记录字段，策略执行后续实现 |
| 创建/更新信息 | 创建人、创建时间、更新人、更新时间 |

### 4.2 部门 Department

部门用于承载租户内组织结构、成员归属和项目协作关系。

| 字段 | 说明 |
|---|---|
| 部门 ID | 系统唯一标识 |
| 所属租户 | 部门必须归属于一个租户 |
| 父部门 | 支持树形结构 |
| 部门名称 | 同一父部门下唯一 |
| 部门编码 | 租户内唯一 |
| 部门负责人 | 可为空，可多人 |
| 状态 | 启用、停用 |

### 4.3 用户 User

用户是平台操作主体，可属于一个租户下的一个或多个部门。

| 字段 | 说明 |
|---|---|
| 用户 ID | 系统唯一标识 |
| 登录账号 | 租户内唯一，支持邮箱或用户名 |
| 昵称/姓名 | 展示名称 |
| 邮箱/手机号 | 联系信息 |
| 所属租户 | 用户必须归属于租户 |
| 所属部门 | 可多部门，需有主部门 |
| 状态 | 未激活、启用、停用、锁定 |
| 外部身份 ID | 预留 SSO/组织同步 |
| 最近登录时间 | 用于安全审计 |

### 4.4 项目 Project

项目是测试资产、应用、环境、成员和质量活动的主要协作空间。

| 字段 | 说明 |
|---|---|
| 项目 ID | 系统唯一标识 |
| 所属租户 | 项目必须归属于租户 |
| 项目名称 | 租户内唯一 |
| 项目编码 | 租户内唯一，建议用于 API 和集成 |
| 项目负责人 | 一个或多个 |
| 关联部门 | 可关联多个部门 |
| 项目状态 | 筹备中、进行中、归档、停用 |
| 项目描述 | 业务说明 |

### 4.5 应用 Application

应用代表项目下的被测系统或子系统，是后续接口、页面、用例、执行任务的重要归属对象。

| 字段 | 说明 |
|---|---|
| 应用 ID | 系统唯一标识 |
| 所属项目 | 应用必须归属于一个项目 |
| 应用名称 | 项目内唯一 |
| 应用编码 | 项目内唯一 |
| 应用类型 | Web 管理后台、HTTP API、混合应用、其他 |
| 应用负责人 | 一个或多个 |
| 默认访问地址 | 可选，环境可覆盖 |
| 仓库/文档链接 | 可选，预留后续集成 |
| 状态 | 启用、停用 |

### 4.6 环境 Environment

环境描述测试运行所需的上下文配置，包括地址、变量、鉴权和使用约束。

| 字段 | 说明 |
|---|---|
| 环境 ID | 系统唯一标识 |
| 所属项目 | 环境必须归属于项目 |
| 所属应用 | 可选；支持项目公共环境和应用专属环境 |
| 环境名称 | 项目或应用范围内唯一 |
| 环境类型 | 开发、测试、预发、生产只读、沙箱、自定义 |
| 基础地址 | API Base URL、Web URL |
| 环境变量 | Key-Value 配置，敏感值加密存储 |
| 鉴权配置 | Token、Cookie、账号凭据引用等，敏感值加密存储 |
| 使用权限 | 可按角色/成员限制 |
| 状态 | 启用、停用 |

### 4.7 角色 Role

角色是一组权限的集合，可作用于平台、租户、项目、应用或环境范围。

| 字段 | 说明 |
|---|---|
| 角色 ID | 系统唯一标识 |
| 所属租户 | 平台内置角色可为空，租户自定义角色必填 |
| 角色名称 | 作用域内唯一 |
| 角色编码 | 作用域内唯一 |
| 角色层级 | 平台级、租户级、项目级、应用级、环境级 |
| 权限集合 | 关联权限点 |
| 是否内置 | 内置角色不可删除，可限制编辑 |
| 状态 | 启用、停用 |

### 4.8 权限 Permission

权限是最小可授权能力，建议以“资源:动作”方式表达。

| 字段 | 说明 |
|---|---|
| 权限 ID | 系统唯一标识 |
| 权限编码 | 全局唯一，如 `project:create` |
| 权限名称 | 展示名称 |
| 资源类型 | tenant、department、user、project、application、environment、role、audit |
| 动作 | view、create、edit、delete、enable、disable、assign、export |
| 描述 | 权限用途说明 |

### 4.9 审计日志 Audit Log

审计日志记录关键操作的主体、对象、动作、结果和上下文。

| 字段 | 说明 |
|---|---|
| 日志 ID | 系统唯一标识 |
| 租户 ID | 归属租户；平台级操作可为空或使用系统租户 |
| 操作人 | 用户 ID、账号、姓名 |
| 操作动作 | 登录、创建、编辑、删除、启停、授权、导出等 |
| 资源类型 | 被操作对象类型 |
| 资源 ID/名称 | 被操作对象标识 |
| 操作结果 | 成功、失败 |
| 变更摘要 | 关键字段变更前后摘要 |
| 请求信息 | IP、User-Agent、Trace ID |
| 时间 | 操作发生时间 |

## 5. 关键用户流程

### 5.1 租户初始化流程

1. 平台超级管理员登录平台。
2. 创建租户，填写租户名称、编码、联系人和初始状态。
3. 创建或指定租户管理员。
4. 系统为租户初始化预置角色和基础权限。
5. 租户管理员登录后维护部门、用户和项目。
6. 系统记录租户创建、管理员授权和初始化操作审计日志。

### 5.2 组织与用户配置流程

1. 租户管理员进入组织管理。
2. 创建部门树，配置部门负责人。
3. 邀请或创建用户，分配主部门和可选兼职部门。
4. 为用户分配租户级角色，或等待项目内授权。
5. 用户首次登录后激活账号。
6. 管理员可停用离职或外部协作用户。

### 5.3 项目与成员配置流程

1. 租户管理员或具备权限的用户创建项目。
2. 录入项目名称、编码、负责人、关联部门和描述。
3. 项目负责人进入项目成员管理。
4. 添加项目成员并分配 ProjectOwner、Tester、Developer、Auditor 等项目级角色。
5. 项目成员根据角色访问项目下的应用、环境和后续测试资产。

### 5.4 应用与环境配置流程

1. 项目负责人在项目下创建应用。
2. 录入应用名称、编码、类型、负责人和默认访问地址。
3. 创建项目公共环境或应用专属环境。
4. 配置 Web URL、API Base URL、变量、鉴权方式和敏感配置。
5. 选择可使用该环境的角色或成员范围。
6. 保存后系统生成环境配置变更审计日志。

### 5.5 权限变更流程

1. 管理员进入角色或成员授权页面。
2. 选择用户、用户组或项目成员。
3. 选择授权范围和角色。
4. 系统校验操作者是否具备授权权限，且不能授予超过自身管理范围的权限。
5. 授权成功后立即生效，并记录授权前后差异。

### 5.6 审计查询流程

1. 审计员或管理员进入审计日志页面。
2. 按时间、操作人、资源类型、动作、结果、项目、应用等条件筛选。
3. 查看审计列表和单条详情。
4. 对需要线下复盘的日志进行导出。
5. 导出行为本身也记录审计日志。

## 6. 功能需求清单

### 6.1 租户管理

| 优先级 | 功能 | 需求描述 |
|---|---|---|
| P0 | 租户列表 | 支持查看租户名称、编码、状态、管理员、创建时间 |
| P0 | 创建租户 | 支持创建租户并校验名称/编码唯一性 |
| P0 | 编辑租户 | 支持编辑名称、联系人、描述等非关键字段 |
| P0 | 启停租户 | 停用后租户内普通用户不可登录和访问数据 |
| P0 | 指定租户管理员 | 支持创建或选择用户作为租户管理员 |
| P1 | 租户详情 | 展示部门数、用户数、项目数、最近活跃信息 |
| P2 | 租户数据保留配置 | 记录数据保留策略字段，后续接入自动执行 |

### 6.2 部门管理

| 优先级 | 功能 | 需求描述 |
|---|---|---|
| P0 | 部门树 | 支持租户内树形部门展示 |
| P0 | 创建部门 | 支持选择父部门并创建子部门 |
| P0 | 编辑部门 | 支持修改部门名称、编码、负责人 |
| P0 | 启停部门 | 停用部门不可再作为新用户主部门 |
| P1 | 调整部门层级 | 支持移动部门到其他父部门下 |
| P1 | 部门成员查看 | 支持查看部门下用户列表 |
| P2 | 批量导入部门 | 支持通过模板导入部门结构 |

### 6.3 用户管理

| 优先级 | 功能 | 需求描述 |
|---|---|---|
| P0 | 用户列表 | 支持按部门、状态、关键词筛选 |
| P0 | 创建/邀请用户 | 支持录入账号、姓名、邮箱、手机号、部门 |
| P0 | 编辑用户 | 支持修改姓名、联系方式、部门 |
| P0 | 启停/锁定用户 | 停用或锁定后禁止登录 |

## 7. 页面/交互建议

### 7.1 信息架构

Web 管理后台建议采用左侧导航 + 顶部租户/项目上下文切换 + 主内容区的结构。

| 一级导航 | 二级页面 | 说明 |
|---|---|---|
| 工作台 | 项目概览 | MVP 可展示基础统计和快捷入口 |
| 组织管理 | 部门管理、用户管理 | 租户管理员使用 |
| 项目管理 | 项目列表、项目详情、成员管理 | 租户管理员和项目负责人使用 |
| 应用管理 | 应用列表、应用详情 | 项目内应用管理 |
| 环境管理 | 环境列表、环境详情 | 项目/应用环境配置 |
| 权限管理 | 角色管理、授权管理 | 租户管理员使用 |
| 审计日志 | 审计查询、审计详情 | 管理员和审计员使用 |
| 平台管理 | 租户管理 | 仅平台超级管理员可见 |

### 7.2 关键页面建议

#### 租户管理页

- 列表字段：租户名称、编码、状态、管理员、项目数、用户数、创建时间、操作。
- 主要操作：创建租户、编辑、启用、停用、指定管理员。
- 停用租户需二次确认，并提示影响范围。

#### 部门管理页

- 左侧为部门树，右侧展示部门详情和成员列表。
- 支持在部门节点上创建子部门、编辑、停用。
- 停用存在启用子部门或启用用户的部门时，应给出阻断或迁移提示。

#### 用户管理页

- 列表支持关键词、部门、状态、角色筛选。
- 用户详情建议使用抽屉展示，包含基础信息、所属部门、角色、项目权限、最近登录。
- 分配角色时需明确授权范围，避免只展示角色名称造成误操作。

#### 项目详情页

- 顶部展示项目状态、负责人、关联部门和成员数。
- Tab 建议包含：概览、成员、应用、环境、审计。
- 项目归档后，页面进入只读态，仅有具备恢复权限的用户可恢复。

#### 应用详情页

- 展示应用基础信息、负责人、默认地址、关联环境。
- 应用类型使用明确枚举，避免自由输入影响后续执行器适配。
- 应用停用后保留历史数据查看入口。

#### 环境配置页

- 表单分区：基础信息、访问地址、环境变量、鉴权配置、使用权限。
- 敏感字段创建后默认只展示掩码，不支持明文回显。
- 保存环境配置前展示变更摘要；高风险环境类型如生产只读需二次确认。

#### 角色与授权页

- 角色详情展示权限树，按资源类型分组。
- 授权页面采用“选择成员 -> 选择范围 -> 选择角色 -> 确认”的路径。
- 禁止用户给他人授予超过自身范围的角色。

#### 审计日志页

- 默认展示最近 7 天日志。
- 筛选项包括时间范围、操作人、动作、资源类型、资源名称、结果、项目、应用。
- 审计详情以抽屉或详情页展示，突出变更摘要、请求信息和关联 Trace ID。

### 7.3 通用交互原则

- 删除、停用、授权、导出等高风险操作需要二次确认。
- 表单保存失败时需明确展示字段级错误和全局错误。
- 所有编码类字段在输入时进行格式提示，建议仅允许字母、数字、下划线和中划线。
- 列表页保留筛选条件和分页状态，方便管理用户连续处理。
- 对无权限页面展示明确的无权限提示，不暴露敏感资源详情。

## 8. 数据与权限规则

### 8.1 数据隔离规则

- 租户是最高数据隔离边界，默认禁止跨租户查询、引用和授权。
- 部门、用户、项目、角色、审计日志必须归属到租户。
- 项目必须归属于一个租户，可关联多个部门。
- 应用必须归属于一个项目。
- 环境必须归属于一个项目，可选归属于一个应用。
- 审计日志必须记录租户上下文；平台级操作需标记为平台操作。
- 后续测试资产、执行任务、报告、缺陷草稿均应继承项目、应用和环境上下文。

### 8.2 唯一性规则

| 对象 | 唯一性要求 |
|---|---|
| 租户编码 | 全局唯一 |
| 部门编码 | 租户内唯一 |
| 用户登录账号 | 租户内唯一 |
| 项目编码 | 租户内唯一 |
| 应用编码 | 项目内唯一 |
| 环境名称 | 同一项目公共环境内唯一；同一应用下唯一 |
| 角色编码 | 作用域内唯一 |
| 权限编码 | 全局唯一 |

### 8.3 状态规则

- 停用租户后，租户内非平台超级管理员用户不可登录或访问租户数据。
- 停用用户后，该用户所有会话应失效，后续不可登录。
- 停用项目后，不可新增应用、环境和成员；历史数据保留只读。
- 归档项目默认只读，不可作为新测试执行目标。
- 停用应用后，不可新增环境或被后续测试资产引用。
- 停用环境后，不可被后续执行任务选择。
- 内置角色不可删除；是否允许编辑由系统配置决定，MVP 建议只读。

### 8.4 权限校验规则

- 前端可控制入口展示，但所有权限必须以后端校验为准。
- 用户访问资源时必须同时满足角色权限和资源归属范围。
- 用户授权他人时，授权范围不得超过自身可管理范围。
- 租户管理员不能访问其他租户数据。
- 项目负责人只能管理被授权项目内成员、应用和环境。
- 审计员只能查看授权范围内的审计日志，不能修改业务数据。
- 敏感环境变量仅允许具备环境编辑权限的用户创建或覆盖，不允许明文查看。

### 8.5 敏感数据规则

- 密码、Token、Cookie、Secret、Access Key 等敏感值必须加密存储。
- 敏感值创建后默认不明文回显，仅展示掩码和最后更新时间。
- 敏感值变更需记录审计日志，但审计日志不得记录明文。
- 导出用户、环境和审计数据时，需要根据权限过滤敏感字段。

## 9. 审计与合规要求

### 9.1 必须审计的操作

| 类别 | 操作 |
|---|---|
| 登录安全 | 登录成功、登录失败、登出、账号锁定 |
| 租户管理 | 创建租户、编辑租户、启用租户、停用租户、指定管理员 |
| 组织用户 | 创建部门、编辑部门、停用部门、创建用户、编辑用户、启停用户 |
| 权限管理 | 创建角色、编辑角色、分配角色、移除角色、修改权限 |
| 项目应用 | 创建项目、编辑项目、归档项目、停用项目、创建应用、停用应用 |
| 环境配置 | 创建环境、编辑地址、修改变量、修改鉴权、启停环境 |
| 数据导出 | 导出审计日志、导出用户列表、导出配置列表 |
| 安全事件 | 无权限访问、越权访问尝试、敏感配置修改失败 |

### 9.2 审计日志内容要求

- 必须记录操作人、操作时间、租户、动作、资源类型、资源标识、操作结果。
- 对配置变更类操作，应记录变更字段、变更前摘要和变更后摘要。
- 对失败操作，应记录失败原因分类，例如权限不足、参数非法、资源不存在、系统异常。
- 必须记录请求 IP、User-Agent 和 Trace ID，便于链路排查。
- 审计日志不可由普通业务用户修改或删除。

### 9.3 合规要求

- 审计日志默认保留周期建议不少于 180 天，MVP 可先固定配置，后续支持租户级策略。
- 敏感值不得出现在页面明文、接口响应明文、日志明文和导出文件中。
- 用户停用、权限移除、租户停用等安全相关操作应即时生效。
- 生产只读环境应作为高风险环境类型处理，默认限制编辑和使用权限。
- 平台应保留后续对接企业 SSO、组织同步、审批流和数据保留策略的扩展字段。

## 10. 验收标准

### 10.1 基础配置闭环验收

- 给定平台超级管理员，可以创建一个租户并指定租户管理员。
- 给定租户管理员，可以创建部门、创建用户、分配租户级角色。
- 给定租户管理员，可以创建项目并指定项目负责人。
- 给定项目负责人，可以添加项目成员、创建应用、创建环境。
- 给定测试工程师，可以查看被授权项目、应用和可用环境。

### 10.2 权限隔离验收

- 未授权用户不能查看、编辑或删除不属于自己的租户、项目、应用和环境。
- 项目成员不能访问未加入项目的数据。
- 只读审计员只能查看审计日志，不能执行配置修改操作。
- 项目负责人不能给成员授予租户管理员或其他超出项目范围的角色。
- 停用用户后，该用户再次访问任意接口均被拒绝。

### 10.3 环境配置验收

- 可以创建项目公共环境和应用专属环境。
- 环境支持维护 Web URL、API Base URL、普通变量和敏感变量。
- 敏感变量保存后不明文回显，接口响应和审计日志中也不包含明文。
- 停用环境后，后续执行模块不可选择该环境；MVP 可通过状态字段和接口约束验证。

### 10.4 审计验收

- 创建、编辑、启停、授权、导出等 P0 操作均生成审计日志。
- 审计日志可按时间、操作人、资源类型、动作、结果筛选。
- 审计详情展示变更摘要、请求信息和 Trace ID。
- 无权限访问和登录失败等安全事件可被记录。

### 10.5 页面体验验收

- 管理后台可以通过导航进入租户、组织、用户、项目、应用、环境、角色和审计页面。
- 列表页具备必要筛选、分页、空状态和错误状态。
- 高风险操作具备二次确认和明确影响提示。
- 表单校验清晰，编码、必填、唯一性等错误可被用户理解。

## 11. 关键风险与待后续细化项

### 11.1 关键风险

| 风险 | 影响 | 应对建议 |
|---|---|---|
| 权限模型过粗 | 后续资产、执行和报告模块可能出现越权或重复改造 | MVP 先统一资源层级和权限编码规范 |
| 权限模型过细 | 研发成本高，管理员配置复杂 | MVP 以预置角色和少量自定义角色为主 |
| 环境敏感信息泄露 | 可能造成被测系统安全风险 | 敏感值加密存储、脱敏展示、审计不记明文 |
| 多租户上下文遗漏 | 后续数据隔离风险高 | 所有核心表和接口强制携带租户上下文 |
| 审计日志过大 | 存储和查询成本增加 | MVP 先保留必要字段，后续引入归档和冷热分层 |
| 组织同步缺失 | 企业落地时用户维护成本高 | 预留外部身份和部门同步字段，后续接入 SSO/LDAP |
| 项目/应用/环境边界不清 | 后续测试资产归属混乱 | WP1 明确项目为协作空间，应用为被测系统，环境为运行上下文 |

### 11.2 待后续细化项

- SSO、LDAP、钉钉、飞书、企业微信等身份与组织同步方案。
- 自定义角色的权限编辑边界和内置角色是否允许复制。
- 环境鉴权配置的具体类型，例如 Token、Cookie、OAuth2、Basic Auth、账号池引用。
- 环境变量继承规则：租户级、项目级、应用级、环境级变量是否支持覆盖。
- 审计日志保留周期、归档策略和导出审批要求。
- 生产只读环境的准入、使用审批和执行限制。
- 用户组或团队组能力是否在 WP1 纳入，还是后续作为权限增强。
- 与后续模型策略的关系：是否需要在 WP1 预留租户/项目/应用的公有云模型开关。
- 与后续测试账号池的关系：账号池归属项目、应用还是环境。
- 与后续企业集成连接器的关系：连接器配置归属租户、项目还是应用。
