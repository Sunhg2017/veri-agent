## 1. 背景与目标

AI 驱动的端到端企业级测试平台需要承载需求解析、测试资产生产、接口/UI/E2E 自动执行、失败诊断、报告分析和企业集成等能力。上述能力都依赖稳定的平台基础底座：清晰的组织边界、可靠的数据隔离、可配置的项目与应用上下文、可审计的权限与操作记录。

WP1 的目标是在 MVP 阶段优先建设企业级测试平台的控制面基础能力，保证后续测试资产、执行任务、模型策略、集成配置、报告数据都能归属于正确的部门、项目、应用和环境，并在权限控制和审计要求下安全运行。

### 1.1 业务目标

- 支持平台以单平台、多部门、多项目、多应用方式管理企业测试资产。
- 建立用户、角色、权限的统一管理能力，为后续资产生产、执行、审批、配置和报告模块复用。
- 建立环境配置能力，支持按项目和应用维护接口、UI、鉴权、变量等测试运行基础信息。
- 建立操作审计能力，满足企业内部追踪、合规、问题定位和安全复盘需求。
- 为后续 WP 的需求资产、用例资产、执行调度、AI Agent、模型策略和企业集成提供统一上下文。

### 1.2 产品目标

- 管理员可以完成部门、用户、项目、应用、环境、角色和权限的基础配置。
- 项目负责人可以管理本项目下的应用、成员、环境和基础配置。
- 普通成员只能访问被授权的项目、应用和环境数据。
- 所有关键写操作、权限变更、登录行为、越权拒绝和配置变更都有可查询审计日志。
- MVP 阶段先保证核心链路闭环，保留组织同步、复杂审批、完整字段级权限等后续扩展点。

### 1.3 成功指标

| 指标 | MVP 目标 |
|---|---|
| 基础配置闭环 | 新租户从创建到项目、应用、环境、成员配置可完整完成 |
| 权限准确性 | 未授权用户无法访问项目、应用、环境和审计数据，后端鉴权覆盖 P0 管理接口 100% |
| 审计覆盖率 | P0 关键操作、越权拒绝和登录安全事件 100% 记录审计日志 |
| 管理效率 | 管理员可在 10 分钟内完成一个租户的基础初始化 |
| 安全底线 | 敏感值不在页面、接口响应、审计、导出、应用日志中明文出现 |
| 扩展适配 | 后续测试资产、执行任务、模型策略可复用租户/项目/应用/环境上下文 |

## 2. 范围与非范围

### 2.1 本期范围

- 租户管理：创建、编辑、启停、查看租户基础信息，绑定租户管理员。
- 部门管理：维护部门树、部门负责人、部门成员关系，支持用户主部门和兼任部门。
- 用户管理：创建/邀请用户、激活用户、启停/锁定用户、分配部门、分配角色、查看用户项目权限。
- 项目管理：创建项目、维护项目基础信息、项目成员、项目状态、项目关联部门。
- 应用管理：在项目下维护被测应用，支持应用类型、负责人和基础访问配置。
- 环境管理：维护项目公共环境和应用专属环境，支持环境变量、服务地址、鉴权配置和启停。
- 角色权限：冻结 MVP 预置角色，支持平台级、租户级、部门级、项目级、应用级、环境级作用域授权。
- 操作审计：记录登录、配置、权限、成员、环境、导出、越权拒绝等关键操作，支持查询和详情查看。
- Web 管理后台：提供基础管理页面和关键表单交互。
- 后续 WP 支撑接口：提供当前用户上下文、项目/应用/环境上下文、有效配置读取和内部审计写入的最小可用能力。

### 2.2 本期非范围

- 不建设完整 SSO/LDAP/企业微信/钉钉/飞书组织同步，仅预留外部身份 ID 和集成字段。
- 不建设复杂审批流，例如项目创建审批、权限申请审批、环境变更审批。
- 不建设测试资产库、用例生成、脚本生成、执行调度和报告看板的完整能力。
- 不建设模型路由、模型密钥管理和 AI Agent 工作流；`allow_public_model`、敏感级别、执行开关、资源池仅作为配置字段保存、读取和审计。
- 不建设跨租户数据分析和集团级合并报表。
- 不建设计费、套餐管理等商业化能力；基础配额仅保留字段，不进入 P0 业务闭环。
- 不建设完整字段级权限策略编辑器和复杂 ABAC 策略。

### 2.3 依赖与假设

- 平台默认存在一个超级管理员初始化入口，用于创建首个 `SuperAdmin`。
- MVP 阶段以 Web 管理后台作为主要使用入口。
- 后端服务需要提供统一租户上下文与权限校验能力，供后续模块复用。
- 审计日志应由服务端统一生成，前端不直接决定审计是否记录。
- 架构设计文件保持不修改；本 PRD 作为产品最终口径，对架构中角色命名与一对多模型差异给出冻结规则，研发实现需按最终 PRD 与架构评审结论对齐。

## 3. 用户角色与权限

### 3.1 MVP 角色命名冻结

MVP 预置角色编码和页面展示统一冻结为：

`SuperAdmin`、`TenantAdmin`、`DepartmentManager`、`ProjectOwner`、`AppOwner`、`Tester`、`Developer`、`Auditor`。

架构文档中历史命名映射如下，仅作实现参考，不在产品页面和测试用例中继续使用旧名。

| 最终角色编码 | 历史/架构近似命名 | 说明 |
|---|---|---|
| SuperAdmin | SystemAdmin | 平台级超级管理员 |
| TenantAdmin | TenantAdmin | 租户管理员 |
| DepartmentManager | DepartmentManager | 部门负责人/部门管理员 |
| ProjectOwner | ProjectAdmin/TestLead | 项目负责人 |
| AppOwner | 应用负责人 | 应用负责人 |
| Tester | Tester | 测试工程师 |
| Developer | Developer | 研发工程师 |
| Auditor | Viewer/只读审计员 | 审计只读角色 |

### 3.2 角色定义

| 角色 | 角色定位 | 典型用户 | 默认作用域 | 权限范围 |
|---|---|---|---|---|
| SuperAdmin | 平台初始化与全局治理 | 平台运维、平台负责人 | Platform | 创建/启停租户、绑定租户管理员、查看平台级审计 |
| TenantAdmin | 单租户组织与权限管理 | 企业测试平台管理员 | Tenant | 管理本租户部门、用户、角色、项目、应用、环境和租户审计 |
| DepartmentManager | 部门成员和部门项目协同 | QA 负责人、研发负责人 | Department | 管理本部门成员，查看本部门关联项目，发起/维护授权范围内项目 |
| ProjectOwner | 项目交付和质量资产负责人 | 测试经理、项目经理 | Project | 管理本项目基础信息、成员、应用、环境和项目审计 |
| AppOwner | 单应用测试配置负责人 | 应用研发负责人、应用 QA | Application | 管理本应用基础信息、应用专属环境和应用审计 |
| Tester | 资产生产与执行使用者 | QA | Project/Application/Environment | 查看授权项目、应用和环境，使用启用环境 |
| Developer | 协作查看与问题定位 | RD | Project/Application | 查看授权项目、应用、环境脱敏配置和审计摘要 |
| Auditor | 合规审计和问题复盘 | 内控、安全、审计人员 | Tenant/Project/Application/Environment | 查看授权范围内审计日志，不修改业务数据 |

### 3.3 权限模型

MVP 采用 `RBAC + 资源作用域 + 少量策略条件`。所有授权通过角色绑定表达，角色绑定必须包含主体、角色、作用域和租户上下文。

| 权限层级 | 说明 | 示例 |
|---|---|---|
| 平台级 | 跨租户的系统管理权限 | 创建租户、查看平台级审计 |
| 租户级 | 租户内组织、用户、角色和项目管理权限 | 创建部门、邀请用户、创建项目 |
| 部门级 | 部门成员和部门关联项目协同权限 | 维护本部门成员、查看本部门项目 |
| 项目级 | 单项目内成员、应用、环境和配置权限 | 添加项目成员、创建应用 |
| 应用级 | 单应用配置与环境使用权限 | 编辑应用信息、管理应用专属环境 |
| 环境级 | 特定环境的查看、编辑和使用权限 | 编辑测试环境变量、使用预发环境执行 |

### 3.4 权限点命名

权限点采用 `{resource}:{action}`，P0 权限点冻结如下。

| 资源 | P0 权限点 |
|---|---|
| tenant | `tenant:read`、`tenant:create`、`tenant:edit`、`tenant:enable`、`tenant:disable`、`tenant:assign_admin` |
| department | `department:read`、`department:create`、`department:edit`、`department:enable`、`department:disable`、`department:member_manage` |
| user | `user:read`、`user:create`、`user:edit`、`user:enable`、`user:disable`、`user:lock`、`user:assign_role` |
| project | `project:read`、`project:create`、`project:edit`、`project:archive`、`project:disable`、`project:member_manage` |
| application | `application:read`、`application:create`、`application:edit`、`application:disable` |
| environment | `environment:read`、`environment:create`、`environment:edit`、`environment:disable`、`environment:use` |
| role | `role:read`、`role:create`、`role:edit`、`role:bind`、`role:unbind` |
| audit | `audit:read`、`audit:export`、`audit:write_internal` |
| config | `config:read`、`config:edit` |
| secret | `secret:reference` |

## 4. 核心业务对象

### 4.1 租户 Tenant

租户是平台数据隔离的最高业务边界，代表一个企业、事业部或独立组织。

| 字段 | 规格 |
|---|---|
| 租户 ID | 系统生成，唯一，不可编辑 |
| 租户名称 | 必填，2-64 字符，租户内展示名称，平台内名称建议唯一 |
| 租户编码 | 必填，3-32 字符，仅允许字母、数字、下划线、中划线，全局唯一，创建后不可编辑 |
| 状态 | 启用、停用；默认启用 |
| 管理员 | 一个或多个 `TenantAdmin` |
| 联系信息 | 联系人、邮箱、手机号；邮箱/手机号按格式校验 |
| 数据保留策略 | MVP 仅记录字段，策略执行后续实现 |
| 创建/更新信息 | 创建人、创建时间、更新人、更新时间 |

### 4.2 部门 Department

部门用于承载租户内组织结构、成员归属和项目协作关系。

| 字段 | 规格 |
|---|---|
| 部门 ID | 系统生成，唯一，不可编辑 |
| 所属租户 | 必填，来自认证上下文或 SuperAdmin 创建租户流程 |
| 父部门 | 可空，支持树形结构；禁止循环和移动到自身子部门 |
| 部门名称 | 必填，2-64 字符，同一父部门下唯一 |
| 部门编码 | 必填，3-32 字符，租户内唯一，创建后不可编辑 |
| 部门负责人 | 可为空，可多人，通过 `DepartmentManager` 角色绑定表达 |
| 状态 | 启用、停用；默认启用 |

### 4.3 用户 User

用户是平台操作主体，可属于一个租户下的一个或多个部门。

| 字段 | 规格 |
|---|---|
| 用户 ID | 系统生成，唯一，不可编辑 |
| 登录账号 | 必填，3-64 字符，租户内唯一，支持邮箱或用户名，创建后不可编辑 |
| 昵称/姓名 | 必填，2-64 字符 |
| 邮箱/手机号 | 至少填写一个；邮箱、手机号按格式校验 |
| 所属租户 | 必填，用户必须归属于一个租户 |
| 所属部门 | 可多部门，必须有且仅有一个主部门，主部门必须启用 |
| 状态 | 未激活、启用、停用、锁定；邀请创建默认未激活，本地创建可默认启用 |
| 外部身份 ID | 可选，预留 SSO/组织同步 |
| 最近登录时间 | 系统维护，不可编辑 |

### 4.4 项目 Project

项目是测试资产、应用、环境、成员和质量活动的主要协作空间。

| 字段 | 规格 |
|---|---|
| 项目 ID | 系统生成，唯一，不可编辑 |
| 所属租户 | 必填，项目必须归属于一个租户 |
| 项目名称 | 必填，2-64 字符，租户内唯一 |
| 项目编码 | 必填，3-32 字符，租户内唯一，创建后不可编辑 |
| 项目负责人 | 必填，支持多人，通过 `ProjectOwner` 项目成员/角色绑定表达 |
| 关联部门 | 必填，可关联多个部门，必须且只能指定一个主责部门；关联部门必须启用且属于同一租户 |
| 项目状态 | 筹备中、进行中、归档、停用；默认筹备中 |
| 项目描述 | 可选，0-500 字符 |
| 敏感级别 | PUBLIC、INTERNAL、CONFIDENTIAL、STRICT；默认 INTERNAL |
| 是否允许公有云模型 | 可选配置字段，WP1 只保存、读取、审计，不实现模型路由 |

### 4.5 应用 Application

应用代表项目下的被测系统或子系统，是后续接口、页面、用例、执行任务的重要归属对象。

| 字段 | 规格 |
|---|---|
| 应用 ID | 系统生成，唯一，不可编辑 |
| 所属项目 | 必填，应用必须归属于一个项目 |
| 应用名称 | 必填，2-64 字符，项目内唯一 |
| 应用编码 | 必填，3-32 字符，项目内唯一，创建后不可编辑 |
| 应用类型 | WEB_ADMIN、HTTP_API、MIXED、OTHER；默认 WEB_ADMIN |
| 应用负责人 | 必填，支持多人，通过 `AppOwner` 应用作用域角色绑定表达 |
| 默认访问地址 | 可选 URL，环境可覆盖 |
| 仓库/文档链接 | 可选 URL，预留后续集成 |
| 敏感级别 | 继承项目，允许覆盖 |
| 是否允许公有云模型 | 继承项目，允许覆盖；WP1 只保存、读取、审计 |
| 状态 | 启用、停用；默认启用 |

### 4.6 环境 Environment

环境描述测试运行所需的上下文配置，包括地址、变量、鉴权和使用约束。环境支持两类归属：项目公共环境和应用专属环境。

| 字段 | 规格 |
|---|---|
| 环境 ID | 系统生成，唯一，不可编辑 |
| 所属项目 | 必填，环境必须归属于项目 |
| 所属应用 | 项目公共环境为空，应用专属环境必填 |
| 环境名称 | 必填，2-64 字符；项目公共环境在项目公共环境范围唯一，应用专属环境在同一应用下唯一 |
| 环境编码 | 必填，3-32 字符，同环境归属范围唯一，创建后不可编辑 |
| 环境类型 | DEV、TEST、STAGING、PROD_READONLY、SANDBOX、CUSTOM；默认 TEST |
| Web URL | 可选 URL |
| API Base URL | 可选 URL |
| 环境变量 | Key-Value 配置；Key 必填且同环境唯一；普通变量可明文存储，敏感变量仅保存密钥引用或密文引用 |
| 鉴权配置 | Token、Cookie、Basic Auth、OAuth2、账号凭据引用等；敏感值不明文入库 |
| 使用权限 | 可按角色/成员限制，默认项目成员可查看，`Tester` 可使用启用环境 |
| 执行开关 | `allow_api_execution`、`allow_ui_execution`、`allow_e2e_execution`；生产只读默认全部关闭 |
| 状态 | 启用、停用；默认启用 |

### 4.7 角色 Role

角色是一组权限的集合，可作用于平台、租户、部门、项目、应用或环境范围。

| 字段 | 规格 |
|---|---|
| 角色 ID | 系统生成，唯一，不可编辑 |
| 所属租户 | 平台内置角色可为空，租户自定义角色必填 |
| 角色名称 | 作用域内唯一 |
| 角色编码 | 使用冻结编码或租户自定义编码，作用域内唯一 |
| 角色层级 | Platform、Tenant、Department、Project、Application、Environment |
| 权限集合 | 关联权限点 |
| 是否内置 | 内置角色不可删除，MVP 不允许编辑内置角色权限 |
| 状态 | 启用、停用 |

### 4.8 权限 Permission

权限是最小可授权能力，以“资源:动作”表达。

| 字段 | 规格 |
|---|---|
| 权限 ID | 系统生成，唯一，不可编辑 |
| 权限编码 | 全局唯一，如 `project:create` |
| 权限名称 | 展示名称 |
| 资源类型 | tenant、department、user、project、application、environment、role、audit、config、secret |
| 动作 | read、create、edit、enable、disable、archive、assign、bind、unbind、export、use |
| 描述 | 权限用途说明 |

### 4.9 审计日志 Audit Log

审计日志记录关键操作的主体、对象、动作、结果和上下文。

| 字段 | 规格 |
|---|---|
| 日志 ID | 系统生成，唯一，不可编辑 |
| 租户 ID | 归属租户；平台级操作使用平台作用域标识 |
| 操作人 | 用户 ID、账号、姓名；系统任务标记 actor_type |
| 操作动作 | 事件编码，如 `PROJECT_CREATE`、`AUTH_DENIED` |
| 资源类型 | 被操作对象类型 |
| 资源 ID/名称 | 被操作对象标识 |
| 操作结果 | SUCCESS、FAILED、DENIED |
| 变更摘要 | 字段级变更前后摘要，敏感字段脱敏 |
| 请求信息 | IP、User-Agent、Trace ID |
| 失败原因 | 权限不足、参数非法、资源不存在、状态非法、系统异常等 |
| 时间 | 操作发生时间 |

## 5. 关键用户流程

### 5.1 超级管理员初始化流程

1. 部署完成后，平台通过受控初始化入口创建首个 `SuperAdmin`。初始化入口可采用一次性启动参数、初始化 CLI 或受保护初始化 API，生产环境只能执行一次。
2. 初始化需填写账号、姓名、邮箱或手机号，并设置初始密码或生成一次性激活链接。
3. 初始密码必须在首次登录后强制修改；一次性激活链接默认 24 小时内有效，使用后立即失效。
4. 初始化完成后写入 `SUPER_ADMIN_INIT` 审计，记录执行来源、时间、结果，不记录密码或 Token。
5. 若系统已存在启用的 `SuperAdmin`，再次调用初始化入口必须拒绝并写入失败审计。

### 5.2 租户初始化流程

1. `SuperAdmin` 登录平台。
2. 创建租户，填写租户名称、编码、联系人和初始状态。
3. 创建或指定一个或多个 `TenantAdmin`。
4. 系统为租户初始化预置角色、权限点和基础配置。
5. 租户管理员收到邀请或初始化通知后完成激活。
6. 租户管理员登录后维护部门、用户和项目。
7. 系统记录租户创建、管理员授权、角色初始化和初始化失败操作审计日志。

### 5.3 租户管理员创建流程

1. `SuperAdmin` 在租户创建流程中创建新用户或选择已有同租户用户。
2. 系统校验用户归属租户、状态和账号唯一性。
3. 系统绑定 `TenantAdmin` 角色，作用域为该租户。
4. 若用户为未激活状态，发送邀请激活链接；若用户已启用，授权立即生效。
5. 授权结果写入 `TENANT_ADMIN_ASSIGN` 审计；失败写入 `TENANT_ADMIN_ASSIGN_FAILED`。

### 5.4 用户邀请/激活流程

1. 管理员创建/邀请用户，填写登录账号、姓名、邮箱或手机号、主部门、兼任部门和初始角色。
2. 系统创建 `未激活` 用户并生成一次性激活链接，链接默认 7 天有效。
3. 用户打开激活链接，设置密码并确认基础信息。
4. 系统校验链接有效、租户启用、用户未停用/未锁定、主部门启用。
5. 激活成功后用户状态变为 `启用`，旧激活链接失效，写入 `USER_ACTIVATE` 审计。
6. 激活链接过期、重复使用或用户已停用时，激活失败并提示联系管理员；安全相关失败写入审计。

### 5.5 登录流程

1. 用户输入租户编码或通过租户域名进入登录页，提交账号和密码。
2. 系统校验租户状态、用户状态、密码和登录失败次数。
3. 登录成功后生成访问会话，返回用户信息、租户上下文、角色摘要、菜单权限和默认项目上下文。
4. 连续 5 次密码错误锁定账号 30 分钟，或由管理员手动解锁；登录失败提示不得泄露账号是否存在。
5. 登录成功写入 `LOGIN_SUCCESS` 审计；登录失败、账号锁定写入安全审计。

### 5.6 登出流程

1. 用户点击登出。
2. 服务端撤销当前会话和刷新令牌。
3. 前端清理本地会话信息并跳转登录页。
4. 系统写入 `LOGOUT` 审计。重复登出或会话已失效时返回成功态或明确已失效态，不恢复会话。

### 5.7 会话过期流程

1. 访问令牌默认有效期 2 小时，刷新令牌默认有效期 7 天；具体值可配置。
2. 访问令牌过期且刷新令牌有效时，可刷新会话并写入 `TOKEN_REFRESH` 审计。
3. 刷新令牌过期、被撤销、用户停用/锁定、租户停用时，刷新失败并要求重新登录。
4. 前端收到 401 后跳转登录页；重新登录后是否回到原页面由前端保存来源地址决定。

### 5.8 用户停用后的会话失效流程

1. 管理员停用或锁定用户。
2. 系统立即撤销该用户所有启用会话，递增用户权限/会话版本，使旧 Token 无法继续访问。
3. 被停用用户再次访问任意 API 返回 401 或 403，具体按认证是否通过区分；不得继续执行业务方法。
4. 系统写入 `USER_DISABLE` 或 `USER_LOCK` 审计，并对旧会话访问写入 `AUTH_DENIED` 或 `SESSION_REVOKED_ACCESS` 审计。

### 5.9 组织与用户配置流程

1. `TenantAdmin` 进入组织管理。
2. 创建部门树，配置 `DepartmentManager`。
3. 邀请或创建用户，分配主部门和可选兼任部门。
4. 为用户分配租户级角色，或等待项目内授权。
5. 用户首次登录后激活账号。
6. 管理员可停用离职或外部协作用户。

### 5.10 项目与成员配置流程

1. `TenantAdmin`、具备授权的 `DepartmentManager` 或具备 `project:create` 权限的用户创建项目。
2. 录入项目名称、编码、负责人、关联部门、主责部门和描述。
3. `ProjectOwner` 进入项目成员管理。
4. 添加项目成员并分配 `ProjectOwner`、`Tester`、`Developer`、`Auditor` 等项目级角色。
5. 项目成员根据角色访问项目下的应用、环境和后续测试资产。

### 5.11 应用与环境配置流程

1. `ProjectOwner` 在项目下创建应用。
2. 录入应用名称、编码、类型、负责人和默认访问地址。
3. 创建项目公共环境或应用专属环境。
4. 配置 Web URL、API Base URL、变量、鉴权方式和敏感配置。
5. 选择可使用该环境的角色或成员范围。
6. 保存前展示变更摘要；保存后系统生成环境配置变更审计日志。

### 5.12 权限变更流程

1. 管理员进入角色或成员授权页面。
2. 选择用户或部门，MVP P0 不提供用户组。
3. 选择授权范围和角色。
4. 系统校验操作者是否具备授权权限，且不能授予超过自身管理范围的权限。
5. 授权成功后立即生效，权限缓存失效，并记录授权前后差异。

### 5.13 审计查询流程

1. `Auditor` 或管理员进入审计日志页面。
2. 按时间、操作人、资源类型、动作、结果、项目、应用等条件筛选。
3. 查看审计列表和单条详情。
4. P0 支持页面查询和详情查看；P1 支持导出。
5. 导出行为本身也记录审计日志。

### 6.9 P0 API 契约与错误码要求

P0 接口需在研发前形成 OpenAPI 或等价接口契约，至少包含请求/响应 DTO、权限点、作用域来源、审计事件编码、错误码和分页筛选规则。

| 类型 | 统一规则 |
|---|---|
| 分页 | `page_no` 从 1 开始，`page_size` 默认 20，最大 100；返回 `total`、`items` |
| 排序 | 默认按 `created_at desc`；非法排序字段返回参数非法 |
| 筛选 | 所有列表默认按认证上下文过滤租户和授权范围，禁止客户端覆盖 `tenant_id` |
| 幂等 | 创建类接口 P0 不要求幂等键，但重复提交必须被唯一性约束拦截，不产生重复数据 |
| 错误码 | `UNAUTHORIZED`、`FORBIDDEN`、`VALIDATION_ERROR`、`CONFLICT`、`NOT_FOUND`、`INVALID_STATE`、`SECRET_POLICY_VIOLATION`、`SYSTEM_ERROR` |
| 越权返回 | 未登录返回 401；已登录无权限返回 403；跨租户资源可统一返回 403 或 404，但不得泄露资源详情 |

### 7.3 通用交互原则

- 删除、停用、锁定、归档、授权、解绑、敏感变量变更、生产只读环境变更、导出等高风险操作需要二次确认。
- 二次确认必须展示操作对象、影响范围和不可见后果；取消后不产生业务变更，不记录成功审计。
- 表单保存失败时需明确展示字段级错误和全局错误。
- 所有编码类字段在输入时进行格式提示，仅允许字母、数字、下划线和中划线。
- 列表页保留筛选条件和分页状态。
- 对无权限页面展示明确无权限提示，不暴露敏感资源详情。

### 7.4 异常流

| 场景 | 系统行为 |
|---|---|
| 未登录访问 | 返回 401，前端跳转登录 |
| 会话过期 | 尝试刷新；刷新失败跳转登录 |
| 无权限访问页面 | 展示无权限页，不展示资源详情 |
| 直接调用越权 API | 后端返回 403 或统一 404，写入拒绝审计 |
| 参数校验失败 | 返回字段级错误，不写成功审计；安全相关失败可写失败审计 |
| 唯一性冲突 | 返回冲突错误，提示冲突字段 |
| 状态非法 | 返回状态非法错误，提示当前状态不可执行该操作 |
| 审计写入失败 | 主流程不阻断，进入补偿队列并记录系统日志 |
| 密钥服务不可用 | 敏感配置保存失败，普通配置不受影响；返回明确错误 |

## 8. 数据与权限规则

### 8.1 数据隔离规则

- 租户是最高数据隔离边界，默认禁止跨租户查询、引用和授权。
- 部门、用户、项目、角色、审计日志必须归属到租户。
- 项目必须归属于一个租户，可关联多个部门，且必须有一个主责部门。
- 部门负责人、项目负责人、应用负责人均支持多人，通过角色绑定或成员关系表达，不使用单一负责人字段作为唯一事实来源。
- 应用必须归属于一个项目。
- 环境必须归属于一个项目，可选归属于一个应用；`app_id` 为空表示项目公共环境，非空表示应用专属环境。
- 审计日志必须记录租户上下文；平台级操作需标记为平台操作。
- 后续测试资产、执行任务、报告、缺陷草稿均应继承项目、应用和环境上下文。

### 8.2 唯一性规则

| 对象 | 唯一性要求 |
|---|---|
| 租户编码 | 全局唯一 |
| 部门编码 | 租户内唯一 |
| 部门名称 | 同一父部门下唯一 |
| 用户登录账号 | 租户内唯一 |
| 项目编码 | 租户内唯一 |
| 项目名称 | 租户内唯一 |
| 应用编码 | 项目内唯一 |
| 应用名称 | 项目内唯一 |
| 环境编码/名称 | 项目公共环境范围内唯一；同一应用下唯一 |
| 环境变量 Key | 同一环境内唯一 |
| 角色编码 | 作用域内唯一 |
| 权限编码 | 全局唯一 |

### 8.3 状态流

#### 租户状态

| 当前状态 | 允许流转 | 禁止流转/限制 |
|---|---|---|
| 启用 | 停用 | 无 |
| 停用 | 启用 | 停用期间租户内普通用户不可登录，旧会话失效 |

#### 用户状态

| 当前状态 | 允许流转 | 禁止流转/限制 |
|---|---|---|
| 未激活 | 启用、停用 | 不可登录 |
| 启用 | 停用、锁定 | 可登录并访问授权资源 |
| 锁定 | 启用、停用 | 不可登录，旧会话失效 |
| 停用 | 启用 | 不可登录，旧会话失效 |

#### 项目状态

| 当前状态 | 允许流转 | 限制 |
|---|---|---|
| 筹备中 | 进行中、停用 | 可维护成员、应用、环境 |
| 进行中 | 归档、停用 | 可正常使用 |
| 归档 | 进行中、停用 | 只读，不可新增成员、应用、环境 |
| 停用 | 筹备中、进行中 | 不可新增成员、应用、环境，历史数据只读 |

#### 应用状态

| 当前状态 | 允许流转 | 限制 |
|---|---|---|
| 启用 | 停用 | 可维护应用和环境 |
| 停用 | 启用 | 不可新增环境，不可作为新资产或执行目标 |

#### 环境状态

| 当前状态 | 允许流转 | 限制 |
|---|---|---|
| 启用 | 停用 | 可被授权使用 |
| 停用 | 启用 | 不可被后续执行选择 |

#### 角色状态

| 当前状态 | 允许流转 | 限制 |
|---|---|---|
| 启用 | 停用 | 内置角色不可停用 |
| 停用 | 启用 | 停用角色不参与权限计算 |

### 8.4 权限校验规则

- 前端可控制入口展示，但所有权限必须以后端校验为准。
- 用户访问资源时必须同时满足角色权限和资源归属范围。
- 用户授权他人时，授权范围不得超过自身可管理范围。
- 租户管理员不能访问其他租户数据。
- 项目负责人只能管理被授权项目内成员、应用和环境。
- 应用负责人只能管理授权应用及其专属环境。
- 审计员只能查看授权范围内的审计日志，不能修改业务数据。
- 敏感环境变量仅允许具备环境编辑权限的用户创建或覆盖，不允许明文查看。
- 权限变更、角色停用、用户停用后应立即使权限缓存失效。

### 8.5 敏感数据规则

- 密码、Token、Cookie、Secret、Access Key、OAuth Secret 等敏感值必须加密存储或仅保存密钥引用。
- 普通变量可明文存储；敏感变量不得明文入库，不得出现在接口响应、页面、审计、导出和应用日志中。
- 敏感值创建后默认不明文回显，仅展示掩码、密钥引用摘要和最后更新时间。
- 敏感值变更需记录审计日志，但审计日志只记录“是否变更”、字段名和脱敏摘要。
- MVP 如暂未接入企业 Vault/KMS，必须通过可替换 `SecretProvider` 保存密文或密钥引用，并保留迁移到 Vault/KMS 的字段。
- 导出用户、环境和审计数据时，需要根据权限过滤敏感字段。

### 8.6 导出范围取舍

| 导出项 | MVP 优先级 | 规则 |
|---|---|---|
| 审计日志导出 | P1 | 支持 CSV，按当前筛选和授权范围导出，导出行为审计，敏感字段脱敏 |
| 用户列表导出 | P2 | 不进入 P0/P1，可后续实现 |
| 环境配置导出 | P2 | 不进入 P0/P1，避免敏感配置泄露 |
| 租户/项目/应用列表导出 | P2 | 不进入 P0/P1 |

## 9. 审计与合规要求

### 9.1 P0 必须审计的操作

| 类别 | 事件编码 |
|---|---|
| 登录安全 | `SUPER_ADMIN_INIT`、`LOGIN_SUCCESS`、`LOGIN_FAILED`、`LOGOUT`、`TOKEN_REFRESH`、`SESSION_EXPIRED`、`SESSION_REVOKED_ACCESS`、`ACCOUNT_LOCKED` |
| 租户管理 | `TENANT_CREATE`、`TENANT_UPDATE`、`TENANT_ENABLE`、`TENANT_DISABLE`、`TENANT_ADMIN_ASSIGN` |
| 组织用户 | `DEPARTMENT_CREATE`、`DEPARTMENT_UPDATE`、`DEPARTMENT_ENABLE`、`DEPARTMENT_DISABLE`、`USER_INVITE`、`USER_ACTIVATE`、`USER_CREATE`、`USER_UPDATE`、`USER_ENABLE`、`USER_DISABLE`、`USER_LOCK` |
| 权限管理 | `ROLE_BIND`、`ROLE_UNBIND`、`ROLE_CREATE`、`ROLE_UPDATE`、`PERMISSION_DENIED` |
| 项目应用 | `PROJECT_CREATE`、`PROJECT_UPDATE`、`PROJECT_ARCHIVE`、`PROJECT_DISABLE`、`PROJECT_MEMBER_ADD`、`PROJECT_MEMBER_REMOVE`、`APPLICATION_CREATE`、`APPLICATION_UPDATE`、`APPLICATION_DISABLE` |
| 环境配置 | `ENVIRONMENT_CREATE`、`ENVIRONMENT_UPDATE`、`ENVIRONMENT_DISABLE`、`ENV_VARIABLE_UPDATE`、`AUTH_CONFIG_UPDATE`、`SECRET_REFERENCE_CHANGE` |
| 数据导出 | `AUDIT_EXPORT` |
| 安全事件 | `AUTH_DENIED`、`CROSS_TENANT_ACCESS_DENIED`、`SECRET_POLICY_VIOLATION`、`SENSITIVE_CONFIG_UPDATE_FAILED` |

### 9.2 审计日志内容要求

- 必须记录操作人、操作时间、租户、动作、资源类型、资源标识、操作结果。
- 对配置变更类操作，应记录变更字段、变更前摘要和变更后摘要。
- 对失败操作，应记录失败原因分类，例如权限不足、参数非法、资源不存在、系统异常。
- 必须记录请求 IP、User-Agent 和 Trace ID，便于链路排查。
- 审计日志不可由普通业务用户修改或删除。
- 审计写入失败不阻断主流程，但必须进入补偿队列；补偿成功后审计可查。

### 9.3 审计查询与导出

- 审计查询默认最近 7 天，最长查询范围 90 天。
- `TenantAdmin` 可查询本租户审计；`ProjectOwner` 查询项目范围审计；`AppOwner` 查询应用范围审计；`Auditor` 查询授权范围审计；`SuperAdmin` 查询平台级审计。
- 审计详情展示字段级 diff；敏感字段必须脱敏。
- P1 审计导出仅支持 CSV；导出内容必须按权限和筛选条件生成。

### 9.4 合规要求

- 审计日志默认保留周期建议不少于 180 天，MVP 可先固定配置，后续支持租户级策略。
- 敏感值不得出现在页面明文、接口响应明文、日志明文、审计明文和导出文件中。
- 用户停用、权限移除、租户停用等安全相关操作应即时生效。
- 生产只读环境应作为高风险环境类型处理，默认限制编辑和使用权限。
- 平台应保留后续对接企业 SSO、组织同步、审批流和数据保留策略的扩展字段。

## 10. 验收标准

### 10.1 基础配置闭环验收

| 编号 | Given | When | Then |
|---|---|---|---|
| AC-001 | 系统未初始化 | 执行受控初始化并创建 `SuperAdmin` | 初始化成功，首次登录强制修改密码，生成 `SUPER_ADMIN_INIT` 审计 |
| AC-002 | `SuperAdmin` 已登录 | 创建租户并指定 `TenantAdmin` | 租户创建成功，预置角色生成，管理员授权成功，相关审计可查 |
| AC-003 | `TenantAdmin` 已登录 | 创建部门、邀请用户、分配租户级角色 | 用户为未激活或启用状态，主部门有效，授权立即生效 |
| AC-004 | `TenantAdmin` 已登录 | 创建项目并指定多个 `ProjectOwner`、多个关联部门和一个主责部门 | 项目创建成功，主责部门属于关联部门，负责人通过角色绑定体现 |
| AC-005 | `ProjectOwner` 已登录 | 添加项目成员、创建应用、创建项目公共环境和应用专属环境 | 成员、应用、两类环境均创建成功，审计可查 |
| AC-006 | `Tester` 已被授权项目环境 | 查看项目、应用和环境 | 只能看到授权范围内数据，可使用启用环境，不可编辑配置 |

## 11. 关键风险与待后续细化项

### 11.1 关键风险

| 风险 | 影响 | 应对建议 |
|---|---|---|
| 权限模型过粗 | 后续资产、执行和报告模块可能出现越权或重复改造 | MVP 统一资源层级、权限编码和作用域矩阵 |
| 权限模型过细 | 研发成本高，管理员配置复杂 | MVP 以预置角色为主，自定义角色放 P1 |
| 环境敏感信息泄露 | 可能造成被测系统安全风险 | 敏感值加密或密钥引用存储、脱敏展示、审计不记明文 |
| 多租户上下文遗漏 | 后续数据隔离风险高 | 所有核心表和接口强制携带租户上下文 |
| 审计日志过大 | 存储和查询成本增加 | MVP 默认时间范围查询，后续引入归档和冷热分层 |
| 组织同步缺失 | 企业落地时用户维护成本高 | 预留外部身份和部门同步字段，后续接入 SSO/LDAP |
| 项目/应用/环境边界不清 | 后续测试资产归属混乱 | WP1 明确项目为协作空间，应用为被测系统，环境为运行上下文 |

### 11.2 待后续细化项

- SSO、LDAP、钉钉、飞书、企业微信等身份与组织同步方案。
- 自定义角色的权限编辑边界和内置角色是否允许复制。
- 环境鉴权配置的完整类型，例如 Token、Cookie、OAuth2、Basic Auth、账号池引用。
- 环境变量继承规则：租户级、项目级、应用级、环境级变量是否支持覆盖。
- 审计日志保留周期、归档策略和导出审批要求。
- 生产只读环境的准入、使用审批和执行限制。
- 用户组或团队组能力是否在 WP1 纳入，还是后续作为权限增强。
- 与后续模型策略的关系：WP1 仅预留租户/项目/应用的公有云模型开关，不实现路由。
- 与后续测试账号池的关系：账号池归属项目、应用还是环境。
- 与后续企业集成连接器的关系：连接器配置归属租户、项目还是应用。
