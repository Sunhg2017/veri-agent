## 1. 使用约定

### 1.1 矩阵标记

| 标记 | 含义 | 研发/测试解释 |
|---|---|---|
| 全量 | 对该资源和动作具备完整权限 | 仍必须受租户、状态、敏感数据规则约束 |
| 只读 | 仅可查看列表、详情或摘要 | 不允许创建、编辑、状态变更、授权、导出 |
| 可用 | 可读取并作为后续测试执行、配置解析或上下文切换的目标 | 不代表可编辑 |
| 授权范围 | 以角色绑定的 `scope_type/scope_id` 为准 | 可为租户、部门、项目、应用或环境范围 |
| 关联范围 | 通过部门项目关联、项目成员、应用归属、环境归属推导 | 后端必须校验资源归属 |
| 无 | 默认无权限 | 菜单、按钮不可见，API 必须拒绝 |

### 1.2 资源与动作编码

| 资源 | 动作 | 权限点编码 |
|---|---|---|
| tenant | 查看、创建、编辑、启用、停用、指定管理员 | `tenant:read`、`tenant:create`、`tenant:edit`、`tenant:enable`、`tenant:disable`、`tenant:assign_admin` |
| department | 查看、创建、编辑、启用、停用、成员管理 | `department:read`、`department:create`、`department:edit`、`department:enable`、`department:disable`、`department:member_manage` |
| user | 查看、创建/邀请、编辑、启用、停用、锁定、分配角色 | `user:read`、`user:create`、`user:edit`、`user:enable`、`user:disable`、`user:lock`、`user:assign_role` |
| role | 查看、创建、编辑、绑定、解绑 | `role:read`、`role:create`、`role:edit`、`role:bind`、`role:unbind` |
| project | 查看、创建、编辑、归档、停用、成员管理 | `project:read`、`project:create`、`project:edit`、`project:archive`、`project:disable`、`project:member_manage` |
| application | 查看、创建、编辑、停用、负责人管理 | `application:read`、`application:create`、`application:edit`、`application:disable`、`application:owner_manage` |
| environment | 查看、创建、编辑、停用、使用、授权用户管理 | `environment:read`、`environment:create`、`environment:edit`、`environment:disable`、`environment:use`、`environment:user_manage` |
| config | 查看、编辑 | `config:read`、`config:edit` |
| audit | 查看、导出、内部写入 | `audit:read`、`audit:export`、`audit:write_internal` |
| context | 查看当前上下文、切换项目/应用/环境、读取有效上下文 | `context:read`、`context:switch`、`context:effective_read` |

说明：

- 架构文档中的 `tenant:manage`、`department:manage`、`user:manage`、`project:manage`、`application:manage`、`environment:manage`、`config:manage` 在接口实现时可映射为本文件拆分后的创建、编辑、状态变更和成员管理动作。
- `audit:write_internal` 仅供平台服务身份使用，不作为 Web 管理后台普通用户按钮能力。
- `context` 是后续 WP 读取当前用户、租户、项目、应用、环境和有效配置的支撑资源，不提供业务数据修改能力。

## 4. 授权与越权约束

1. 前端菜单和按钮可按本矩阵隐藏，但所有接口必须以后端鉴权结果为准。
2. 用户访问资源时必须同时满足权限点、角色作用域、租户归属、资源归属和资源状态要求。
3. 用户授权他人时，角色层级、权限集合和作用域不得超过操作者自身可管理范围。
4. `TenantAdmin` 只能管理当前租户，不能跨租户查看、授权、导出或统计。
5. `ProjectOwner` 只能管理绑定项目，不能授予 `TenantAdmin`，不能管理非绑定项目成员。
6. `AppOwner` 只能管理绑定应用及其应用专属环境，不能管理项目公共环境，不能授予项目级以上角色。
7. `DepartmentManager` 默认不具备项目写权限；如需创建或编辑项目，必须额外绑定项目级或租户级权限。
8. `Tester` 可使用授权启用环境，但不能编辑环境、配置、成员或授权。
9. `Developer` 默认只能查看授权项目、应用、环境脱敏信息，不能使用环境触发执行。
10. `Auditor` 只能查看授权范围内审计日志和资源摘要，不能修改业务数据。
11. 权限变更、角色停用、用户停用、租户停用后必须立即使会话或权限缓存失效。
12. 跨租户资源访问应返回 `403` 或统一 `404`，不得泄露资源详情。

## 7. 高风险操作二次确认规则

### 7.1 通用规则

1. 删除、停用、锁定、归档、授权、解绑、导出、敏感配置修改、生产只读环境修改均必须二次确认。
2. 二次确认必须展示操作对象、对象编码、当前状态、影响范围、不可见后果和确认/取消按钮。
3. 取消二次确认不得产生业务变更，不记录成功审计。
4. 确认后由后端再次校验权限、状态和资源归属；前端确认不能替代后端鉴权。
5. 成功、失败和权限拒绝按审计规则记录；敏感字段只记录字段名、是否变化、掩码或密钥引用摘要。
6. 高风险操作完成后必须刷新权限缓存、会话状态或列表数据，避免继续展示已撤销能力。

### 7.2 操作级规则

| 高风险操作 | 触发场景 | 二次确认展示内容 | 阻断/限制规则 | 审计要求 |
|---|---|---|---|---|
| 停用租户 | `tenant:disable` | 租户名称、编码、租户管理员、影响用户数、旧会话失效、业务数据只读保留 | 仅 `SuperAdmin`；不能停用系统租户 | 记录停用前后状态、操作者、租户范围 |
| 停用部门 | `department:disable` | 部门名称、编码、子部门、成员数、关联项目 | 存在启用子部门、启用用户主部门或启用项目主责部门时阻断 | 记录状态变化和阻断原因 |
| 停用/锁定用户 | `user:disable`、`user:lock` | 用户账号、姓名、角色、影响会话、禁止登录说明 | 不能停用最后一个可用 `TenantAdmin`；停用后立即撤销会话 | 记录状态、会话撤销结果、失败原因 |
| 归档/停用项目 | `project:archive`、`project:disable` | 项目名称、编码、成员数、应用数、环境数、只读/停用影响 | 归档后只读；停用后不可新增成员、应用、环境 | 记录状态和影响范围 |
| 停用应用 | `application:disable` | 应用名称、编码、所属项目、环境数、后续资产目标影响 | 停用后不可新增环境，不可作为新测试资产目标 | 记录状态和所属项目 |
| 停用环境 | `environment:disable` | 环境名称、编码、环境类型、执行开关、使用权限 | 启用中的执行任务处理由 WP9 扩展；WP1 只阻断新使用 | 记录状态和执行开关 |
| 授权/解绑 | `role:bind`、`role:unbind`、`user:assign_role` | 被授权人、角色、作用域、资源名称、权限摘要 | 不能超过操作者自身范围；不能解绑导致租户无管理员 | 记录授权前后差异，权限缓存失效 |
| 导出 | `audit:export` 或后续数据导出 | 导出类型、筛选条件、数据范围、脱敏说明、预计条数 | MVP 审计导出为 P1；无导出权限不可见 | 记录导出条件、结果、文件摘要，不记录敏感值 |
| 敏感配置修改 | `config:edit`、`environment:edit` | 字段名、所属环境/应用/项目、变更摘要、脱敏说明 | 敏感值不得明文回显或写入审计；必须走 `SecretProvider` | 记录字段名、是否变化、掩码或 `secret_ref` 摘要 |
| 生产只读环境保存 | `environment:edit` | 环境名称、生产标识、只读说明、执行开关状态 | 生产环境默认执行开关关闭；保存需明确确认 | 记录环境类型、配置项、执行开关变化 |

## 8. 敏感数据与导出可见规则

1. 密码、Token、Cookie、Secret、Access Key、OAuth Secret 等敏感值不得明文入库、回显、进入审计、导出或应用日志。
2. 具备环境或配置编辑权限的用户只能创建、覆盖或删除敏感值，不能读取明文。
3. 普通变量可按权限明文展示；敏感变量只展示掩码、密钥引用摘要和最后更新时间。
4. 审计详情中的 `diff_json` 对敏感字段只记录“是否变化”、字段名和脱敏摘要。
5. 导出必须按当前用户权限范围和筛选条件生成，并过滤敏感字段。
6. `SuperAdmin`、`TenantAdmin` 也不得查看敏感值明文。

## 9. MVP 非范围权限能力

| 能力 | MVP 结论 | 保留方式 |
|---|---|---|
| 字段级权限策略编辑器 | 非范围 | 仅按页面和接口返回脱敏字段；字段级 diff 用于审计，不提供管理员配置字段权限 |
| 复杂 ABAC 策略 | 非范围 | `condition_json` 预留给后续数据权限、时间窗、环境类型等条件，不建设策略 DSL 或策略引擎 |
| 组织同步 | 非范围 | 预留外部身份 ID、集成字段和部门同步字段，不接入 SSO/LDAP/企业微信/钉钉/飞书组织同步 |
| 权限申请审批流 | 非范围 | 项目创建审批、权限申请审批、环境变更审批不在 WP1 MVP 实现 |
| 自定义角色权限编辑 | P1 | MVP 内置角色只读；租户自定义角色、复制角色和编辑权限集合后续实现 |
| 用户组/团队组授权 | 非范围 | MVP 授权主体以用户和部门为主，不建设独立用户组能力 |
| 跨租户数据分析 | 非范围 | 租户默认强隔离，不提供集团级合并报表 |
| 硬删除与恢复工作台 | 非范围 | 基础对象优先软删除或状态流，不提供普通用户硬删除能力 |
| 细粒度导出中心 | P1 | MVP 仅明确导出权限、脱敏和审计规则；审计 CSV 导出为 P1 |

## 10. 测试落地口径

1. 每个资源动作至少覆盖一个正向用例、一个跨租户越权用例、一个跨作用域越权用例和一个状态非法用例。
2. 菜单可见性按角色登录验证，直接 URL 访问必须再次验证无权限页和后端 `403/404`。
3. 按钮可见性只作为前端体验验收，不能替代 API 自动化鉴权用例。
4. 授权、解绑、停用用户、停用租户后，旧 Token 不得保留已撤销权限。
5. 环境、配置、审计、导出相关用例必须验证敏感字段脱敏。
6. 高风险操作必须验证二次确认内容、取消无副作用、确认后审计和缓存失效。
