## 1. 页面目标

让测试工程师和测试负责人在浏览器内完成 WP10 P0 主链路：基于 WP9 run 生成报告，查看报告详情和证据摘要，触发失败诊断，生成缺陷草稿，并导出脱敏摘要。页面必须帮助用户理解 AI 诊断只是建议，最终判断需要人工确认。

## 2. 导航与权限

| 项 | 设计 |
|---|---|
| 路由 | `#reports` |
| 菜单名 | 报告诊断 |
| 入口权限 | `report:read` |
| 生成报告 | `report:generate` |
| AI 诊断 | `report:diagnose` |
| 缺陷草稿审阅 | `report:manage` |
| 导出摘要 | `report:export` |

无 `report:read` 权限时不显示入口；直达路由展示无权限态，不触发业务 API。按钮显隐只做体验优化，服务端权限、项目 scope、报告状态和配置开关是最终准入。

## 3. 页面结构

| 区域 | 内容 |
|---|---|
| 顶部指标 | READY 报告数、生成中数、失败报告数、AI 诊断开关、导出开关。 |
| 报告筛选 | 项目、状态、runId、触发来源、生成时间、失败分类。 |
| 报告列表 | 报告状态、executionRunId 摘要、run 状态、失败桶、生成时间、traceId 和操作入口。 |
| 生成报告面板 | executionRunId、requestKey、原因、幂等结果和错误提示。 |
| 报告详情 | run summary、节点状态计数、失败分类、evidence manifest、redaction policy。 |
| 失败诊断 | 规则分类、AI 候选根因、置信度、依据引用、下一步动作、人工确认提示。 |
| 缺陷草稿 | 标题、复现摘要、影响范围、优先级建议、证据引用、payload preview 和审阅动作。 |
| 导出面板 | JSON/Markdown/PDF/Word 脱敏导出、manifest、digest、fieldSetVersion、下载状态和脱敏扫描结果。 |

## 4. 核心交互

### 4.1 生成报告

1. 点击生成报告。
2. 输入或选择 `executionRunId`，填写可选 requestKey 和原因。
3. 提交后按钮进入 loading，成功后选中报告详情。
4. 如果返回 `idempotentReplay=true`，显示已回放既有报告。
5. `REPORT_SOURCE_RUN_NOT_READY` 展示源 run 尚未具备 handoff 的错误态和 traceId。

### 4.2 报告详情

1. 点击列表项加载详情。
2. 顶部展示状态、生成时间、schemaVersion、sourceRunDigest 和 traceId。
3. run summary 和 nodeStatusCounts 使用紧凑统计区。
4. evidence manifest 按 WP9、WP8、WP3、WP5 分组展示，只展示 sourceWp、sourceType、schemaVersion、summaryKeys、digest 和 redaction flags。
5. redaction policy 固定展示禁止字段状态，避免用户误以为可下载原始日志。

### 4.3 失败诊断

1. READY 报告显示诊断按钮。
2. 页面先展示规则分类；AI 诊断 loading 时保留规则结果。
3. AI 成功后展示候选根因、confidence、evidenceRefs 和 nextActions。
4. AI 失败或策略阻断时展示降级原因、errorCode 和 traceId。
5. 所有 AI 输出旁展示人工确认提示，不使用确定性措辞。

### 4.4 缺陷草稿

1. 诊断完成或规则分类可用时显示生成草稿按钮。
2. 草稿区展示 title、reproductionSummary、impactSummary、prioritySuggestion、evidenceRefs 和 payload preview。
3. `report:manage` 用户可标记 REVIEWED 或 DISMISSED。
4. P0 不显示发送 Jira/禅道/飞书按钮。

### 4.5 导出摘要

1. `report:export` 用户可选择 JSON 或 Markdown。
2. 导出成功后展示 schemaVersion、fieldSetVersion、contentDigest、aggregateOnly 和 redactionPolicy。
3. 导出被阻断时展示 blockedReason、policyCode 和 traceId。
4. 页面不渲染包含禁止字段的导出正文。

## 5. 表单校验

| 字段 | 校验 |
|---|---|
| projectId | 必填，来自当前上下文或项目选择器。 |
| executionRunId | 必填，UUID 格式。 |
| requestKey | 可选，1-128 字符，只允许字母、数字、`-`、`_`、`.`、`:`。 |
| reason | 可选，最多 200 字符，不允许明显 secret/token 文本。 |
| exportType | 必填，`JSON` 或 `MARKDOWN`。 |
| draftStatus | 只能在 `DRAFT/REVIEWED/DISMISSED` 间按服务端允许流转。 |

前端校验只做体验优化；后端仍必须完整校验和脱敏扫描。

## 6. 状态展示

| 状态 | UI 表现 |
|---|---|
| QUEUED | 显示排队中和可刷新提示。 |
| GENERATING | 显示生成中、sourceRunDigest 和骨架屏。 |
| READY | 展示详情、诊断、草稿和导出入口。 |
| FAILED | 展示错误码、traceId、重试入口和源 run 摘要。 |
| ARCHIVED | 只读态，隐藏诊断、草稿和导出新动作。 |
| AI_RUNNING | 诊断区 loading，规则分类保留。 |
| AI_READY | 展示 AI 建议和人工确认提示。 |
| AI_FAILED | 展示降级原因，保留规则分类。 |

## 7. Loading/Empty/Error

| 场景 | 行为 |
|---|---|
| 首次加载 | 骨架屏，不阻塞导航。 |
| 无报告 | 展示空态和生成入口，若无 generate 权限则只展示空态。 |
| 无权限 | 展示无权限态，不请求业务 API。 |
| 生成中 | 详情区使用稳定尺寸骨架，避免布局跳动。 |
| 诊断失败 | 保留规则分类，展示 errorCode、traceId 和重试条件。 |
| 导出阻断 | 展示 policyCode，不展示敏感命中值本身。 |
| 后端 409 | 展示状态冲突和建议刷新或重试。 |

## 8. 响应式

1. 桌面端使用左列表右详情或顶部筛选加主详情布局。
2. 390px 窄屏下筛选、列表、统计和详情纵向堆叠。
3. 长 runId、digest、traceId、errorCode、evidenceRef 必须换行，不产生横向页面溢出。
4. evidence manifest 在窄屏使用分组列表，不使用复杂表格横向滚动作为唯一阅读方式。
5. 操作按钮保持稳定高度，loading 文案不改变按钮宽度导致布局跳动。

## 9. 安全与脱敏

1. 不展示 secret、token、cookie、Authorization、password、lease token、`secret://` 原文或完整 secretRef。
2. 不展示 runner stdout/stderr、请求响应正文、webhook payload、raw prompt、raw response、provider error 原文。
3. evidence 只展示 source、schemaVersion、summaryKeys、digest、count 和 redaction flags。
4. AI 输出先经过服务端策略，前端仍需对 DOM 文本做禁止字段 smoke 扫描。
5. 错误提示使用 errorCode、traceId 和脱敏 message。

## 10. 可测性

1. 关键按钮有稳定 accessible name：生成报告、重试生成、触发诊断、生成缺陷草稿、审阅草稿、驳回草稿、导出 JSON、导出 Markdown。
2. 关键区域使用稳定 data-testid：`reports-workbench`、`reports-list`、`report-generate-panel`、`report-detail`、`report-diagnosis`、`report-defect-drafts`、`report-export-panel`。
3. API client 放在 `portal-web/src/api/reports.ts`，所有后端响应经过 normalize helper，兼容 snake_case/camelCase。
4. Vitest 覆盖 normalize、权限、表单校验、状态按钮和敏感字段不渲染。
5. Playwright smoke 覆盖桌面和 390px 视口下生成、详情、诊断、草稿、导出和 DOM 敏感字段扫描。

## 11. 前端验收

1. 无 `report:read` 权限不显示入口，直达路由展示无权限态。
2. 可生成报告并在列表和详情看到 READY 状态。
3. 报告详情展示 run summary、节点计数、evidence manifest 和 redaction policy。
4. 诊断视图展示规则分类、AI 置信度、依据引用和人工确认提示。
5. 缺陷草稿可生成、审阅或 dismiss，不出现外部发送动作。
6. 导出面板展示 manifest、digest 和脱敏策略。
7. 桌面和 390px 窄屏无明显遮挡或横向页面溢出。
8. 页面 DOM 不包含 secret/token/cookie/Authorization/lease token/raw prompt/raw response 等禁止字段。
