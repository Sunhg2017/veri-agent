# WP10 报告与失败诊断 - 研发任务拆解

| 项目 | 内容 |
|---|---|
| 工作包 | WP10 报告与失败诊断 |
| 角色产出 | 五角色联合任务拆解 |
| 文档性质 | 正式研发前可执行 Story/Task 清单 |
| 当前口径 | 以 `platform-api` + `portal-web` 为报告控制面，P0 消费 WP9 脱敏 run export 和 WP8/WP3/WP5 摘要；AI 诊断通过 WP2，不能读取或导出敏感原文 |
| 版本 | v0.3 |
| 日期 | 2026-06-17 |

## 1. 拆解原则

1. 先冻结报告 schema、证据 manifest 和脱敏红线，再做 AI 诊断和缺陷草稿。
2. 每个任务必须有项目 scope、权限、审计、traceId、schemaVersion 和 redaction policy。
3. WP10 不直接读写 WP8/WP9/WP3/WP5 表；跨 WP 输入必须通过应用服务、导出接口或明确 port。
4. AI 诊断输入必须是脱敏、裁剪、可审计上下文，输出必须标明置信度、依据摘要和人工确认要求。
5. P0 不建设 runner 原始产物归档、外部缺陷系统写入、BI 数仓、PDF/Word 完整文件导出和生产容量承诺。

## 13. P0 完成定义

1. 可基于 WP9 `REPORT_HANDOFF` 和脱敏 run export 创建 READY 报告快照。

7. `mvn -B -pl platform-api test`、`cd portal-web && npm test`、`cd portal-web && npm run build`、DB validation 和 WP10 quality gate 通过。
