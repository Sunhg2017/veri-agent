## 1. 结论

截至 WP10-M10 异步生成 worker 收口，WP10 当前承诺范围无剩余 P0 功能开发项。M8E 已补充当前分支本地准出执行记录，M9 已补齐 WP3/WP5 aggregate-only evidence adapter，M10 已补齐 `QUEUED/GENERATING` 后台执行器和 stale 恢复；剩余工作只剩目标环境发布前按对应环境 release gate 执行验证、填写发布记录，以及后续专项另行立项。

`WP10-8.2 前端操作说明` 已由 `WP10-报告与失败诊断-前端操作说明.md` 补齐；`WP10-8.3 运维 Runbook` 已由 `WP10-报告与失败诊断-运维Runbook.md` 补齐；`WP10-8.4 发布准出说明` 已由 `WP10-报告与失败诊断-发布准出说明.md` 补齐；`WP10-8.5 剩余工作盘点` 由本文补齐。

## 4. 发布前必做

目标环境发布前建议执行：

```bash
bash scripts/wp10_quality_gate.sh
mvn -B -pl platform-api test
cd portal-web && npm test
cd portal-web && npm run build
git diff --check
```

当前分支 M8E/M9/M10 已在本地执行核心 release gate 或定向准出验证并通过；目标环境发布仍需在对应环境重跑并填写环境、开关、commit、责任人和跳过项。

如发布只包含文档变更，可按影响面执行：

```bash
rg -n "WP10-8.5|M8D|剩余工作盘点|当前 WP10 范围无剩余 P0 功能开发项" README.md doc/mvp/final/engineering/WP10-* doc/mvp/final/engineering/当前实现基线.md
git diff --check
cd portal-web && npm test -- --run src/api/reports.test.ts src/permissions.test.ts
cd portal-web && npm run build
```

涉及 Java、API、DB、权限、审计、模型调用、导出、安全或前端运行时代码变更时，不得只按文档门禁准出，必须追加 Maven、DB validation、Java 行数门禁、WP10 quality gate、前端 Playwright smoke 或对应专项验证。

## 5. 范围变更触发条件

后续如出现以下任一变化，应重新打开 WP10 需求、技术设计、测试策略和发布准出说明：

1. 报告输入源新增 WP3/WP5 以外的其他跨 WP evidence，或 WP3/WP5 adapter 扩大到非 aggregate-only 明细。
2. 外部缺陷系统从 preview 变为真实写入。
3. 导出从 JSON/Markdown 摘要升级为 PDF/Word/文件下载。
4. AI 诊断上下文扩大到更多 evidence、日志或用户上传内容。
5. 前端新增批量导出、订阅、团队级看板或趋势视图。
6. 生产环境需要容量、压测、保留周期、归档和删除策略承诺。
