# 当前实现基线

| 项目 | 内容 |
|---|---|
| 适用范围 | 当前代码、迁移脚本、验证脚本和现行工程文档 |
| 服务形态 | 单个 Java 服务 `platform-api` |
| 工作包关系 | WP1、WP2、WP3 是任务/领域拆分，不是服务拆分 |
| API 字段风格 | JSON 使用 camelCase |
| 分页口径 | 请求使用 `index`、`size`；响应使用 `items`、`index`、`size`、`total` |
| SQL 维护 | MyBatis Mapper XML，不在 Java 代码维护 SQL |
| 租户口径 | 当前不建设多租户，权限和数据边界下沉到部门、项目、应用、环境和资源作用域 |

## 1. 服务与模块

当前后端只有一个 `platform-api` Java 服务，承载：

1. WP1 平台基础底座：初始化、认证、管理控制面、RBAC、审计、上下文集成能力。
2. WP2 模型接入层：模型供应商、Prompt、模型调用、策略校验、成本与调用审计。
3. WP3 资产管理：需求、接口、页面、业务流程、测试用例、步骤和追踪关系。
4. WP8 测试数据与账号池：数据集、账号池、租借、释放、清理任务控制面、跨 WP 引用契约、数据集/租借脱敏导出摘要、`#test-data` 前端工作台和 WP8 quality gate。
5. WP9 执行编排与任务调度：执行计划、DAG、运行状态机、队列认领、scheduler、webhook/cron、WP6 dispatch、report handoff 和脱敏导出控制面。
6. WP10 报告与失败诊断：报告生成/查询/重试/归档、同项目历史快照对比、可选异步生成 worker、stale `GENERATING` 恢复、WP9/WP8/WP3/WP5 aggregate-only evidence manifest、规则/AI 失败诊断、平台内缺陷草稿、JSON/Markdown 脱敏导出、`#reports` 前端工作台、前端操作说明、运维 Runbook、发布准出说明、剩余工作盘点、本地准出执行记录、顶层文档基线一致性收口、M9 WP3/WP5 evidence adapter 和 M10 异步生成 worker；当前 WP10 范围无剩余 P0 功能开发项。

WP2/WP3 复用 WP1 上下文校验和审计写入时，通过 Spring 应用服务在同进程内调用，不通过 HTTP 回调本服务，不维护 WP2/WP3 到 WP1 的 `platform-api` 地址或服务令牌配置。

## 2. API 契约

统一响应 envelope：

```json
{
  "code": "OK",
  "message": "success",
  "traceId": "trc_xxx",
  "data": {}
}
```

校验错误响应：

```json
{
  "code": "VALIDATION_ERROR",
  "message": "请求字段校验失败",
  "traceId": "trc_xxx",
  "data": {
    "fieldErrors": [
      {
        "field": "code",
        "reason": "must match ..."
      }
    ]
  }
}
```

分页请求统一继承 `BasePageRequest`：

| 参数 | 说明 |
|---|---|
| `index` | 页码索引，从 0 开始，默认 0。 |
| `size` | 每页条数，默认 20，最大 100。 |

分页响应统一使用：

```json
{
  "items": [],
  "index": 0,
  "size": 20,
  "total": 0
}
```

登录响应使用 `accessToken`、`refreshToken`、`sessionId`、`tokenType`、`expiresAt`，不使用 snake_case 字段。

## 3. 数据与权限

当前实现是单平台模型，不包含 `base_tenant` 表，不在业务表维护 `tenant_id`。数据库迁移以 `db/migration/wp1` 中现有脚本为准。

主要边界：

1. 部门用于组织归属和协作授权。
2. 项目是测试资产、模型策略和执行上下文的主要工作空间。
3. 应用归属于项目。
4. 环境支持项目公共环境和应用专属环境。
5. 权限通过预置角色、权限点、资源作用域和角色绑定表达。
6. 审计按平台、部门、项目、应用、环境、资源对象和操作者查询，不按租户隔离。

## 4. 验证入口

后端当前主验证：

```bash
mvn -B -pl platform-api test
```

脚本静态检查：

```bash
bash -n scripts/wp_all_integration_test.sh scripts/wp1_wp2_deploy.sh scripts/wp1_wp2_integration_test.sh scripts/wp2_quality_gate.sh scripts/wp2_model_access_smoke.sh scripts/wp2_module_policy_smoke.sh scripts/wp1_db_profile_smoke.sh
```

WP2 模块策略 smoke 使用：

```bash
bash scripts/wp2_module_policy_smoke.sh
```

WP9 执行编排准出使用：

```bash
bash scripts/wp9_quality_gate.sh
WP9_GATE_MODE=release WP9_SCHEDULER_SMOKE=managed WP9_WEBHOOK_HTTP_SMOKE=managed bash scripts/wp9_quality_gate.sh
```

WP8 测试数据与账号池准出使用：

```bash
bash scripts/wp8_quality_gate.sh
WP8_GATE_MODE=release WP8_LEASE_CONCURRENCY_SMOKE=managed bash scripts/wp8_quality_gate.sh
```

WP10 报告与失败诊断准出使用：

```bash
bash scripts/wp10_quality_gate.sh
mvn -B -pl platform-api test
cd portal-web && npm test
cd portal-web && npm run build
```

历史 `wp2_strict_integration_smoke.sh`、独立 `model-access` Maven 模块、`8081` 服务端口和 WP2/WP3 到 WP1 的 HTTP 回调配置均不属于当前实现。
