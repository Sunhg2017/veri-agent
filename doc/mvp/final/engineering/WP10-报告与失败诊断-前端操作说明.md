# WP10 报告与失败诊断 - 前端操作说明

| 项目 | 内容 |
|---|---|
| 工作包 | WP10 报告与失败诊断 |
| 文档性质 | 浏览器操作说明、产品验收辅助材料 |
| 当前口径 | 用户可在 `#reports` 工作台完成报告列表、报告生成/重试、报告详情、失败诊断、缺陷草稿审阅、JSON/Markdown/PDF/Word 脱敏导出和真实文件下载，不依赖 curl |
| 日期 | 2026-06-17 |

## 1. 适用范围

本文面向测试工程师、测试负责人、项目负责人和发布负责人，说明如何通过 `portal-web` 的 `报告诊断` 工作台完成 WP10 当前已交付的浏览器操作。

本文不覆盖外部缺陷系统写入、趋势报表、runner 原始产物归档或模型 provider 运维。AI 诊断只作为辅助建议，缺陷草稿只保存在平台内；当前完整报告仍是 aggregate-only 脱敏文档，最终定位和缺陷提交仍需人工确认。

## 2. 入口与权限

| 操作 | 权限 |
|---|---|
| 进入 `#reports`、查看报告列表和详情 | `report:read` |
| 生成报告、重试生成、生成缺陷草稿 | `report:generate` |
| 触发失败诊断 | `report:diagnose` |
| 导出 JSON/Markdown/PDF/Word 脱敏文档与下载文件 | `report:export` |
| 归档报告、审阅草稿、驳回草稿 | `report:manage` |

无 `report:read` 时侧边导航不展示 `报告诊断`，直达 `#reports` 只展示无权限态，不拉取业务数据。按钮显隐和置灰只做体验优化；所有操作仍以服务端权限、项目 scope、报告状态和 WP10 配置开关为准。

## 3. 页面结构

| 区域 | 用途 |
|---|---|
| 顶部指标 | 查看 READY 报告、生成中报告、失败报告和缺陷草稿数量，同时确认生成、诊断、草稿开关。 |
| 报告筛选 | 按 projectId、executionRunId 和 status 筛选报告，并刷新当前列表。 |
| 生成报告 | 填写 projectId、executionRunId、requestKey 和 reason，创建 aggregate-only 报告快照或重试当前 FAILED 报告。 |
| 报告列表 | 查看报告状态、executionRunId、run 状态、失败摘要和 traceId，点击条目切换详情。 |
| 报告详情 | 查看 run summary、节点状态计数、失败桶、sourceRunDigest、traceId、evidence manifest 和 redaction policy。 |
| 失败诊断 | 查看规则分类、AI 诊断状态、候选根因、置信度、证据引用、下一步动作和人工确认提示。 |
| 缺陷草稿 | 生成平台内草稿，查看标题、复现摘要、影响范围、优先级建议、证据引用和 masked payload preview。 |
| 导出与下载 | 生成 JSON、Markdown、PDF 或 Word 脱敏文档，查看 status、fieldSetVersion、contentDigest、manifest、aggregateOnly、redactionPolicy 和下载状态。 |

## 4. 筛选与报告列表

1. 进入 `报告诊断` 后，先确认顶部指标和 health 摘要是否加载成功。
2. 在 `报告筛选` 中填写 projectId。projectId 是列表、生成、诊断、草稿和导出的项目 scope 基础。
3. 如需定位单个 run，填写 executionRunId；该字段必须是 UUID。
4. status 可选择 `READY`、`FAILED`、`GENERATING`、`QUEUED` 或 `ARCHIVED`，也可保持为空查看当前项目下的报告。
5. 点击 `筛选` 或 `刷新` 后查看报告列表。列表为空时，可在具备 `report:generate` 权限的情况下创建第一份报告。
6. 点击列表中的报告条目会加载详情、最新诊断、缺陷草稿和已生成的导出摘要。

## 5. 生成、重试和归档报告

1. 在 `生成报告` 区填写 projectId 和 executionRunId。
2. requestKey 可选，用于幂等生成；同一 executionRunId 和 requestKey 重复提交时，页面会展示已回放既有报告。
3. reason 可选，建议填写本次生成目的或发布验证背景。reason 最多 200 字符，不能输入明显的凭据、原始日志或模型上下文文本。
4. 点击 `生成报告` 后，成功时页面会选中新报告并展示 READY 详情；失败时查看 errorCode、traceId 和错误提示。
5. 当前选中的 FAILED 报告可点击 `重试生成`。重试保留原失败证据并创建新的生成尝试。
6. 不再需要操作的报告可由具备 `report:manage` 的用户点击 `归档`。ARCHIVED 报告进入只读状态，不应继续触发诊断、草稿或新导出。

## 6. 报告详情和证据 Manifest

1. 报告详情顶部展示报告 status、短 ID、schemaVersion、traceId 和 sourceRunDigest。
2. run summary 展示 runStatus、triggerType、nodeCount、failureBucket 等聚合摘要，帮助快速判断失败范围。
3. evidence manifest 按 sourceWp/sourceType 展示来源、schemaVersion、summaryKeys、manifestDigest 和 redactionFlags。
4. evidence manifest 只展示 digest、计数、summary keys 和脱敏策略，不展示 WP8/WP9/WP3/WP5 原始明细。
5. redaction policy 用于确认报告快照、诊断上下文和导出摘要是否遵守 aggregate-only 和禁止字段约束。
6. 需要排障时优先记录 traceId、reportId、executionRunId、sourceRunDigest 和 manifestDigest，再交由后端或运维按 Runbook 追踪。

## 7. 失败诊断

1. READY 报告可点击 `触发诊断`。页面会保留规则分类，同时等待 AI 诊断结果或策略降级结果。
2. `RULE_READY` 表示无模型 fallback 已可用，可作为初步分类参考。
3. `AI_READY` 表示 WP2 模型调用成功，页面展示候选根因、confidence、evidenceRefs、nextActions 和 manualReviewRequired。
4. `AI_FAILED` 或 `REPORT_DIAGNOSIS_POLICY_BLOCKED` 表示模型调用、预算或安全策略阻断；规则分类仍可用于人工排障。
5. AI 输出不应被当作确定结论。页面展示的候选根因和下一步动作必须经过测试负责人或责任工程师确认。

## 8. 缺陷草稿

1. 对 READY 报告点击 `生成缺陷草稿`，系统会基于 report summary、最新诊断和 evidence manifest digest 生成平台内草稿。
2. 草稿字段包括 title、reproductionSummary、impactSummary、prioritySuggestion、evidenceRefs 和 payloadPreview。
3. payloadPreview 只用于人工检查字段映射，固定为 masked preview，不会自动写入 Jira、禅道、飞书或其他外部缺陷系统。
4. 具备 `report:manage` 的用户可将 DRAFT 草稿标记为 `REVIEWED` 或 `DISMISSED`。
5. 当前 P0 不支持在页面内发送外部缺陷；如需创建外部缺陷，应由人工根据草稿内容在目标系统中确认并提交。

## 9. JSON/Markdown/PDF/Word 导出与下载

1. 具备 `report:export` 的用户可点击 `导出 JSON`、`导出 Markdown`、`导出 PDF` 或 `导出 Word`。
2. 导出成功后，页面展示 export status、schemaVersion、fieldSetVersion、contentDigest、aggregateOnly、manifest、redactionPolicy，以及 `downloadReady/downloadFileName/downloadContentType` 等下载摘要。
3. 四类导出都只来自 WP10 已持久化的 aggregate-only 快照，不回读 runner 原始日志、请求/响应正文或模型 provider payload。
4. 如果导出被策略阻断，页面只展示 blockReason、policyCode 和 traceId，不展示命中的敏感值本身。
5. Markdown 更适合人工审阅和发布说明摘录；PDF/Word 用于完整脱敏报告下载，但仍不是原始证据归档包。

## 10. 状态解释

| 状态 | 用户含义 |
|---|---|
| `QUEUED` | 报告生成请求已进入队列或等待处理。 |
| `GENERATING` | 报告快照生成中，可稍后刷新。 |
| `READY` | 报告已可查看详情、诊断、草稿和导出。 |
| `FAILED` | 报告生成失败，可查看 errorCode/traceId 后重试。 |
| `ARCHIVED` | 报告已归档，只保留历史证据和只读详情。 |
| `RULE_READY` | 规则分类已生成，无模型时也可用于人工排障。 |
| `AI_READY` | AI 诊断建议已生成，仍需人工确认。 |
| `AI_FAILED` | AI 诊断降级或失败，规则分类仍保留。 |
| `DRAFT` | 缺陷草稿待审阅。 |
| `REVIEWED` | 缺陷草稿已人工确认。 |
| `DISMISSED` | 缺陷草稿已驳回。 |
| `BLOCKED` | 导出或诊断被策略阻断，需按 traceId 排查策略原因。 |

## 11. 安全与脱敏边界

1. 页面不得展示 secret、token、cookie、Authorization、password、lease token、`secret://` 原文或完整 secretRef。
2. 页面不得展示 runner stdout/stderr、请求正文、响应正文、webhook payload、截图、视频、源码包、raw prompt、raw response 或 provider payload。
3. 报告详情、诊断、缺陷草稿和导出面板只展示 digest、summaryKeys、redactionFlags、计数、状态和脱敏策略。
4. `rawPromptStored=false`、`rawResponseStored=false` 等安全策略键可以展示；它们表示未保存原文，不是敏感内容泄露。
5. 如果浏览器页面、导出摘要或错误提示出现禁止字段样本，应停止发布，保留 traceId，并回归 WP10 redaction smoke、diagnosis redaction eval 和前端 DOM 扫描。

## 12. 常见排障

| 现象 | 处理 |
|---|---|
| 看不到 `报告诊断` | 检查账号是否具备 `report:read`。 |
| 生成按钮置灰 | 检查 `report:generate` 权限、projectId/executionRunId 是否填写，以及 WP10 生成开关是否开启。 |
| executionRunId 校验失败 | 确认输入为 UUID，不要粘贴 run 名称、traceId 或短 ID。 |
| 生成返回源 run 未就绪 | 确认 WP9 run 已达到可报告状态，并具备 `REPORT_HANDOFF` 脱敏摘要。 |
| 重试按钮不可用 | 只有当前选中的 FAILED 报告支持重试生成。 |
| 触发诊断失败 | 查看 errorCode、traceId、诊断开关、报告状态和 WP2 预算/策略。 |
| AI 诊断降级 | 使用规则分类继续人工排障，并按 traceId 查看 WP2 预算、provider 或安全策略原因。 |
| 草稿无法审阅 | 检查 `report:manage` 权限和草稿是否仍为 DRAFT。 |
| 导出被阻断 | 查看 blockReason、policyCode 和 traceId；不要要求页面显示敏感命中值。 |
| 窄屏显示拥挤 | 长 digest/traceId 会换行显示；如出现横向溢出，应回归 WP10 Playwright smoke。 |

## 13. 产品验收清单

1. 用户可不依赖 curl 完成报告筛选、报告生成、FAILED 重试、详情查看和归档。
2. 用户可在报告详情中理解 run summary、节点状态、失败桶、evidence manifest、sourceRunDigest、traceId 和 redaction policy。
3. 用户可触发失败诊断，并能区分规则分类、AI 建议、策略降级和人工确认要求。
4. 用户可生成平台内缺陷草稿，审阅或驳回草稿，且页面不提供外部缺陷系统自动写入。
5. 用户可导出 JSON/Markdown/PDF/Word 脱敏文档，并能看到 manifest、digest、fieldSetVersion、aggregateOnly、redactionPolicy 和下载状态。
6. 无权限、空态、加载中、错误、按钮置灰、traceId/errorCode 和策略阻断提示均可解释。
7. 桌面和 390px 窄屏主链路由 WP10 Playwright smoke 覆盖，无横向页面溢出和按钮重叠。
8. 页面 DOM、导出摘要和错误提示不包含 secret/token/cookie/Authorization/lease token/raw prompt/raw response/runner stdout/stderr 等禁止字段。
