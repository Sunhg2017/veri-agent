# WP10 报告与失败诊断 - M11 平台级真实文件下载与对象存储化专题交付说明

| 项目 | 内容 |
|---|---|
| 工作包 | WP10 报告与失败诊断 |
| 专题 | 平台级真实文件下载与对象存储化 |
| 日期 | 2026-06-23 |

## 1. 目标

把“真实文件下载”从各模块分散的本地落盘逻辑，收敛为平台级统一存储抽象，并将平台默认文件存储 provider 切换为 OSS，同时保留本地开发、测试和显式模块 override 的本地回退能力。

本专题落地两个直接结果：

1. 平台侧形成统一 `OpaqueFileStorage` 抽象和 provider 工厂，业务模块不再直接暴露物理路径，也不直接绑定某个对象存储 SDK。
2. WP10 报告导出从“只返回 inline 预览内容”升级为“预览 + 真实文件下载”，并与 WP7 artifact 存储共用平台能力，默认进入 OSS 存储平面。

## 2. 范围

本轮纳入范围：

1. 平台存储抽象升级为 provider 化，实现 `LocalOpaqueFileStorage`、`OssOpaqueFileStorage`、`PlatformOpaqueStorageFactory`。
2. `PlatformStorageProperties` 与 `PlatformStorageConfiguration` 新增 OSS 配置，并将平台默认 provider 切换为 `oss`。
3. WP7 `UiE2eArtifactStorage` 接入平台级存储工厂；显式配置 `artifactStorageDir` 时继续兼容旧的本地目录模式。
4. WP10 `ReportExportFileStorage` 与 `GET /api/v1/reports/{id}/exports/{exportId}/download` 接入统一平台存储。
5. 本地开发、测试和 `docker-compose` 默认强制回退 `local`，保证无 OSS 配置时仍可稳定开发和验收。

本轮明确不纳入：

1. 预签名 URL、CDN 分发、跨站公开下载链接。
2. 将 WP3 资产导出、WP2/WP5 文本下载等全部下载场景一次性统一改造。
3. 为 WP10 导出新增数据库 `storage_ref` 字段；本轮仍以 `reportId/exportId/exportType` 作为确定性路径规则。
4. 下载链路直接暴露 OSS 公网地址；本轮仍统一通过平台鉴权下载端点回传字节。

## 3. 设计原则

1. 控制面和业务契约只暴露 opaque `storageRef` 或受权下载 API，不暴露宿主机目录结构。
2. 平台存储实现必须阻断路径穿越、非法文件名和受控根目录逃逸。
3. 模块侧继续保留各自权限、脱敏和审计边界，存储层只负责受控读写与清理。
4. 平台默认收敛到 OSS，但 local profile、测试 profile 和显式模块目录 override 必须继续可用，避免开发体验和 CI 被生产默认值反噬。

## 4. 本轮交付

1. `platform-api` 新增公共存储抽象与 provider 工厂：
   - `LocalOpaqueFileStorage`
   - `OssOpaqueFileStorage`
   - `PlatformOpaqueStorageFactory`
   - `StorageRefSupport`
2. 平台默认配置调整为：
   - `application-platform.yml` 默认 `veri-agent.storage.provider=oss`
   - 新增 `veri-agent.storage.oss.endpoint/bucket/access-key-id/access-key-secret/key-prefix`
3. 本地回退策略明确化：
   - `application-local.yml` 强制 `veri-agent.storage.provider=local`
   - `src/test/resources/application.properties` 强制 `veri-agent.storage.provider=local`
   - `src/test/resources/application-db.yml` 强制 `veri-agent.storage.provider=local`
   - `infra/docker-compose.yml` 显式指定 `PLATFORM_STORAGE_PROVIDER=local`
4. WP7 artifact 存储在未显式配置独立目录时，默认改为走平台级统一存储工厂；当 WP7 配置 `artifactStorageDir` 时仍兼容旧目录行为。
5. WP10 导出成功后将脱敏导出内容序列化为真实文件，并通过下载端点返回二进制内容。
6. WP10 导出响应新增：
   - `downloadReady`
   - `downloadFileName`
   - `downloadContentType`
7. 下载接口仍由平台鉴权、审计并回传字节内容，不要求调用方直连 OSS。

## 5. 风险与回滚

主要风险：

1. 生产默认值切到 OSS 后，凡是未显式走 `local` 的运行环境都必须补齐 OSS endpoint、bucket 和 AK 配置，否则 Spring 上下文会在创建 OSS client 时失败。
2. 带 `@ActiveProfiles("db")` 的测试不会自动继承 `spring.profiles.default=local`，必须额外提供 `application-db.yml` 回退 `local`，否则全量测试会误用生产默认值。
3. WP10 下载文件名和 content-type 进入对外契约，需要避免后续随意变更。
4. 当前仍未做预签名 URL 和公网分发，多节点能力来自共享 OSS 存储，但下载链路吞吐仍经过平台 API。

回滚方式：

1. 回退本次平台级 `common.storage` provider 化及 WP7/WP10 接入变更。
2. 将 `PlatformStorageProperties.provider` 默认值与 `application-platform.yml` 默认 provider 改回 `local`。
3. WP10 导出可退回为仅返回 inline 预览内容，不暴露下载端点。
4. 由于本轮未引入数据库迁移，回滚不涉及 DB schema 回退。
