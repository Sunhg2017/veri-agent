# WP10 报告与失败诊断 - M11 平台级真实文件下载与对象存储化专题交付说明

| 项目 | 内容 |
|---|---|
| 工作包 | WP10 报告与失败诊断 |
| 专题 | 平台级真实文件下载与对象存储化 |
| 日期 | 2026-06-23 |

## 1. 目标

把“真实文件下载”从各模块分散的本地落盘逻辑，收敛为平台级统一存储抽象，先以受控本地存储完成一期落地，再为后续切换对象存储 provider 保留稳定接口。

本专题落地两个直接结果：

1. 平台侧形成统一 `OpaqueFileStorage` 抽象，业务模块不再直接暴露物理路径。
2. WP10 报告导出从“只返回 inline 预览内容”升级为“预览 + 真实文件下载”，并与 WP7 artifact 存储共用平台能力。

## 2. 范围

本轮纳入范围：

1. 新增 `OpaqueFileStorage`、`LocalOpaqueFileStorage`、`PlatformStorageProperties`、`PlatformStorageConfiguration`。
2. WP7 `LocalUiE2eArtifactStorage` 改为委托平台级存储实现，保留既有 `UiE2eArtifactStorage` 业务契约。
3. WP10 新增 `ReportExportFileStorage` 与 `GET /api/v1/reports/{id}/exports/{exportId}/download`。
4. `portal-web` Reports Workbench 接入导出文件下载按钮、下载态提示与文件名信息展示。

本轮明确不纳入：

1. S3/OSS/MinIO 等外部对象存储 provider 接入。
2. 预签名 URL、CDN 分发、跨站公开下载链接。
3. 将 WP3 资产导出、WP2/WP5 文本下载等全部下载场景一次性统一改造。
4. 为 WP10 导出新增数据库 `storage_ref` 字段；本轮仍以 `reportId/exportId/exportType` 作为确定性路径规则。

## 3. 设计原则

1. 控制面和业务契约只暴露 opaque `storageRef` 或受权下载 API，不暴露宿主机目录结构。
2. 平台存储实现必须阻断路径穿越、非法文件名和受控根目录逃逸。
3. 模块侧继续保留各自权限、脱敏和审计边界，存储层只负责受控读写与清理。
4. 先统一抽象，再替换 provider，避免业务模块直接绑定某个对象存储 SDK。

## 4. 本轮交付

1. `platform-api` 新增公共存储抽象与本地 provider。
2. WP7 artifact 存储默认落到 `veri-agent.storage.root-dir/<namespace>` 目录体系；当 WP7 显式配置独立目录时仍兼容旧配置。
3. WP10 导出成功后将脱敏导出内容序列化为真实文件，并通过下载端点返回二进制内容。
4. WP10 导出响应新增：
   - `downloadReady`
   - `downloadFileName`
   - `downloadContentType`
5. 前端报告工作台新增“下载文件”按钮，仅在 `downloadReady=true` 时显示。

## 5. 风险与回滚

主要风险：

1. 新增公共存储抽象后，依赖旧默认目录的本地环境需要确认磁盘保留策略。
2. WP10 下载文件名和 content-type 进入对外契约，需要避免后续随意变更。
3. 当前仍是本地磁盘 provider，多节点部署场景下还不具备共享对象存储能力。

回滚方式：

1. 回退本次平台级 `common.storage` 抽象及 WP7/WP10 接入变更。
2. WP10 导出可退回为仅返回 inline 预览内容，不暴露下载端点。
3. 由于本轮未引入数据库迁移，回滚不涉及 DB schema 回退。
