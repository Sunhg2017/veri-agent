## 1. 研发目标

WP1 研发目标是交付企业级测试平台的控制面基础能力，形成可被后续 WP2/WP3/WP8/WP9/WP11 复用的租户、组织、项目、应用、环境、权限、配置、密钥和审计底座。

本计划面向研发执行，不重复 PRD 与架构设计的业务论证，重点回答：

1. 按哪些 Epic 和 Story 进入研发看板。
2. 每个 Story 的目标、任务、依赖、交付物、验收标准、负责人角色和优先级。
3. Iteration 0/1/2/3 分别交付什么、卡什么门槛。
4. 研发前需要冻结哪些工程化附件与规范。
5. 风险、阻塞、协作和评审机制如何管理。

## 2. 范围边界

### 2.1 本计划覆盖

- 工程基础、统一 API 规范、数据库迁移、可观测性和基础质量门禁。
- 初始化、IAM、登录会话、用户状态、租户停用和权限变更失效。
- 租户、部门、用户、成员、负责人、项目、应用、环境的管理闭环。
- RBAC、预置角色、权限点、角色绑定、菜单权限、作用域鉴权和权限缓存。
- 项目公共环境、应用专属环境、普通变量、敏感变量、配置继承和有效配置读取。
- `SecretProvider` 抽象、`LocalEncryptedSecretProvider`、密钥引用、掩码和迁移扩展点。
- 审计模型、审计写入、权限拒绝审计、审计查询、outbox 补偿和脱敏。
- Web 管理控制台的 P0 页面、表单、路由、权限可见性和异常态。
- 后续 WP 支撑接口，包括当前用户上下文、项目/应用/环境上下文、有效配置、内部审计写入。
- 契约测试、权限矩阵测试、多租户隔离测试、敏感数据测试、审计覆盖测试和准出门禁。

### 2.2 本计划不覆盖

- 完整 SSO/LDAP/企微/钉钉/飞书组织同步。
- 项目创建审批、权限申请审批、环境变更审批等复杂审批流。
- 模型路由、模型调用、Prompt 管理、AI Agent 工作流。
- 测试资产库、用例生成、执行调度、报告看板。
- 账号池、测试数据集、企业连接器业务逻辑。
- 计费、套餐、跨租户分析和集团报表。

## 4. Epic 与 Story 拆解

优先级说明：P0 为 MVP 必须交付；P1 为强建议随 WP1 完成或至少预留接口；P2 为后续增强。

| 项 | 内容 |
|---|---|
| 目标 | 建立 `platform-api` 的 WP1 模块化工程基础，支持后续 IAM、org、rbac、project、environment、audit、config、secret 模块并行开发。 |

| 验收标准 | 健康检查、示例分页接口、示例错误响应可运行；所有响应包含 Trace ID；错误码格式与契约一致。 |

| 建议负责人角色 | 测试负责人、项目经理、产品经理、技术负责人。 |
| 优先级 | P0 |

## 7. 风险与阻塞项

| 风险/阻塞 | 影响 | 预警信号 | 应对措施 | 责任角色 |
|---|---|---|---|---|
| OpenAPI 契约迟迟不冻结 | 前后端并行效率下降，测试自动化滞后 | DTO、错误码、枚举频繁变更 | Iteration 0 强制三方评审；破坏性变更走变更单 | 项目经理、后端负责人、前端负责人、测试负责人 |
| 权限矩阵理解不一致 | 越权、菜单不一致、测试返工 | 同一角色前后端行为不同 | 权限矩阵作为唯一来源；每个接口标注权限点和作用域 | 产品经理、后端负责人、测试负责人 |
| 多租户隔离遗漏 | 数据泄露和严重安全缺陷 | API 接收客户端 `tenant_id` 覆盖上下文；SQL 缺少租户条件 | 建立实体基类、拦截器、代码扫描和隔离专项测试 | 后端负责人、测试负责人 |
| SecretProvider 主密钥策略不明确 | 敏感变量无法上线或存在泄露风险 | 本地环境可运行但测试/生产无密钥注入方案 | Iteration 0 冻结运维参数；缺密钥拒绝敏感写入或拒绝启动 | DevOps、后端负责人、安全代表 |
| 审计事件命名不统一 | 审计覆盖率无法验收 | PRD 与架构同义事件混用 | 审计事件字典冻结最终编码；测试按字典验收 | 后端负责人、测试负责人 |
| outbox 补偿不可观测 | 审计丢失难发现 | 重试失败无指标、无告警、无 DEAD 处理 | 定义指标、告警和运维处理流程；准出前演练失败补偿 | DevOps、后端工程师 |
| 前端路由与按钮权限后置 | UI 可见性和 API 鉴权体验割裂 | 页面有入口但操作必然 403 | Iteration 0 冻结路由规范；菜单和按钮基于权限摘要渲染 | 前端负责人、产品经理 |
| 后续 WP 接口被延后 | WP2/WP3/WP8/WP9/WP11 并行受阻 | 后续团队开始直连 WP1 表或复制权限逻辑 | Iteration 2 提供上下文读取，Iteration 3 提供内部审计写入 | 架构师、后端负责人、后续 WP 代表 |
| P1 范围挤占 P0 | 准出延期 | 审计导出、自定义角色等增强项提前消耗主力 | P1 单独标记，不影响 P0 闭环；每周范围复核 | 项目经理、产品经理 |

## 8. 每日协作机制

### 8.1 日站会

- 时间：每个工作日固定 15 分钟。
- 参与：项目经理、产品经理、前端负责人、后端负责人、测试负责人、DevOps，必要时邀请安全和后续 WP 代表。
- 输入：昨日完成、今日计划、阻塞项、接口变更、缺陷风险。
- 输出：阻塞 Owner、当天需评审事项、风险状态更新。

### 8.2 看板规则

| 状态 | 进入条件 | 退出条件 |
|---|---|---|
| Ready | Story 已有目标、任务、依赖、验收标准和接口契约 | 负责人认领并进入开发 |
| In Progress | 开发中，依赖已满足 | 自测通过并提交 PR |
| Code Review | PR 已提交，CI 已运行 | 评审通过且无 P0/P1 阻断问题 |
| Test Ready | 部署到测试环境，测试数据已准备 | 测试开始执行 |
| Testing | 测试执行中 | 缺陷关闭或确认延期 |
| Done | 代码合并、测试通过、文档更新 | 进入迭代验收范围 |

### 8.3 缺陷分级

| 等级 | 定义 | 处理要求 |
|---|---|---|
| Blocker | 阻断初始化、登录、鉴权、租户隔离、敏感值保护、P0 审计或主流程 | 当日响应，准出前必须关闭 |
| Critical | 影响 P0 Story 验收或造成权限/数据一致性风险 | 当前迭代关闭 |
| Major | 影响 P1 或局部体验，可规避 | 评审确认修复版本 |
| Minor | 文案、样式、低风险优化 | 纳入后续优化 |

## 10. 准出门禁

WP1 准出必须同时满足以下条件：

1. P0 功能用例通过率 100%。
2. P0 API 契约测试通过率 100%。
3. 后端 P0 管理接口鉴权覆盖率 100%。
4. P0 审计事件覆盖率 100%。
5. 跨租户访问、越权访问、ID 枚举均被拒绝并记录审计。
6. 敏感值不在页面、接口响应、数据库明文字段、审计、导出和应用日志中出现。
7. 用户停用、租户停用、角色解绑和权限变更后旧会话或权限缓存立即失效。
8. `SecretProvider` 本地加密方案、主密钥注入和备份恢复说明通过安全评审。
9. 审计 outbox 补偿、DEAD 状态、指标和告警可演示。
10. WP2/WP3/WP8/WP9/WP11 可通过 WP1 API 获取上下文、有效配置和写入审计，不直接读写 WP1 表。
11. Web 控制台覆盖 P0 页面，菜单权限、按钮权限、空态、错误态、无权限页、高风险二次确认符合验收要求。
12. P0 Blocker/Critical 缺陷全部关闭；遗留 P1/P2 有明确延期原因、影响面和 Owner。

## 12. 研发执行建议

1. 先锁契约和矩阵，再拆并行任务。WP1 的主要返工风险来自接口、权限和审计口径漂移。
2. RBAC、审计和租户隔离必须作为横切能力前置，不作为业务功能完成后的补丁。
3. Web 控制台每个页面必须同时完成 API 鉴权、菜单入口、按钮权限、无权限态和审计联动。
4. SecretProvider 从第一版环境变量开始接入，禁止先明文落库再补迁移。
5. 后续 WP 支撑接口至少在 Iteration 2 提供可联调版本，避免其他团队绕开 WP1。
6. P1 能力以不影响 P0 准出为原则，审计导出、自定义角色、环境复制、连通性检查可以在 P0 稳定后再进入。
