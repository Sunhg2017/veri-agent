# WP1 权限矩阵测试清单

| 项目 | 内容 |
|---|---|
| 工作包 | WP1 平台基础底座 |
| 文档用途 | QA 测试设计、权限矩阵用例拆分、接口/UI 自动化准备 |
| 覆盖角色 | `SuperAdmin`、`TenantAdmin`、`DepartmentManager`、`ProjectOwner`、`AppOwner`、`Tester`、`Developer`、`Auditor` |
| 覆盖测试域 | 认证会话、多租户隔离、部门权限、项目权限、应用权限、环境权限、角色授权、审计权限、敏感字段、停用状态 |
| 优先级定义 | P0 必测；P1 补充；P2 延后 |

## 1. 测试设计原则

1. 权限测试以服务端鉴权为准，UI 菜单和按钮可见性作为补充验证。
2. 每个资源动作至少覆盖一个正向授权用例、一个同租户越权用例、一个跨租户越权用例。
3. 所有 P0 管理接口必须覆盖鉴权断言、作用域断言、审计断言和敏感字段断言。
4. 所有越权请求必须断言业务未执行、返回 `403` 或统一 `404`、不泄露资源详情，并生成拒绝审计。
5. 权限变更、角色解绑、用户停用、租户停用后必须验证旧 Token 或旧会话立即失效。

## 4. 自动化优先级建议

### 4.1 先做接口自动化

| 优先级 | 范围 | 原因 |
|---|---|---|
| 第一批 | 登录、登出、Token 刷新、用户停用、租户停用、权限解绑旧 Token 失效 | 是权限与会话安全底线，接口稳定后可作为所有测试前置 |
| 第一批 | 多租户隔离、项目/应用/环境详情 ID 枚举、跨租户关联拒绝 | 风险最高，最适合参数化批量覆盖 |
| 第一批 | 角色绑定/解绑、作用域越权、`ProjectOwner` 不得授予 `TenantAdmin` | 权限矩阵核心门禁，必须在 CI 中持续回归 |
| 第一批 | 敏感变量保存、查询、审计脱敏、缺少密钥值、密钥服务失败 | 安全底线，接口断言比 UI 更可靠 |
| 第一批 | P0 审计事件写入和授权范围查询 | 可用接口断言事件、结果、资源、Trace ID、脱敏摘要 |
| 第二批 | 部门树、项目列表、应用列表、环境列表的范围筛选 | 可通过数据驱动覆盖多角色、多作用域 |
| 第二批 | 状态流阻断规则 | 适合做接口状态机测试，避免 UI 操作成本 |

### 4.2 再做 UI 自动化

| 优先级 | 范围 | 原因 |
|---|---|---|
| 第一批 | 8 个角色登录后的菜单可见性和无权限页 | 直接验证角色矩阵在前端落地 |
| 第一批 | 租户、部门、用户、项目、应用、环境 P0 表单字段校验 | 覆盖必填、唯一、不可编辑、格式校验和字段级错误 |
| 第一批 | 高风险操作二次确认 | 停用、锁定、归档、授权、解绑、敏感变量变更必须验证交互文案和取消路径 |
| 第二批 | 环境详情敏感字段展示 | UI 必须无明文、只展示掩码和引用摘要 |
| 第二批 | 审计列表筛选、详情页展示 | 验证筛选控件、空状态、详情脱敏和 Trace ID 展示 |
| 第二批 | 列表空状态和无数据页 | 属于体验验收，风险低于接口鉴权 |

### 4.3 先人工验证

| 优先级 | 范围 | 原因 |
|---|---|---|
| 第一批 | 审计 outbox 补偿、审计写入临时失败恢复 | 依赖故障注入和运维可观测性，早期适合人工专项 |
| 第一批 | 密钥服务不可用、数据库不落明文检查、应用日志检查 | 需要环境级检查和日志/数据库辅助 |
| 第二批 | 审计 CSV 导出内容人工抽查 | P1 能力，需检查文件内容、编码和脱敏 |
| 第二批 | 生产环境只读/执行关闭策略 | 依赖最终 UI 和执行入口实现，首轮人工确认更稳 |
| 延后 | 审计保留策略、用户/环境/项目导出 | P2 或非 P0/P1 范围，进入后续回归池 |

## 5. P0 准出门槛

| 门槛 | 准出要求 |
|---|---|
| P0 功能用例 | 通过率 100%，无阻塞缺陷 |
| P0 接口鉴权 | 覆盖率 100%，无高危越权缺陷 |
| 多租户隔离 | 查询、详情、编辑、授权、审计、配置读取均不可跨租户泄露 |
| RBAC 越权 | 8 个角色核心正向/反向用例全部通过 |
| 停用即时失效 | 用户停用、锁定、租户停用、权限解绑后旧 Token 均失效 |
| 敏感信息 | 页面、接口、审计、导出、日志、数据库均不出现敏感明文 |
| 审计覆盖 | P0 登录、安全、配置、授权、成员、环境、拒绝事件 100% 可查 |

## 6. 后续用例落地建议

1. 建议以 `角色 + 资源 + 动作 + 作用域 + 期望结果` 生成接口自动化数据表，优先覆盖 P0。
2. 接口自动化建议为每个用例自动关联审计查询断言，避免审计漏测。
3. UI 自动化建议只覆盖代表性角色和关键路径，越权组合由接口自动化承担。
4. 敏感字段建议增加关键字黑名单扫描，例如真实 Token、密码、Cookie 值不得出现在响应体、审计详情、导出文件和应用日志。
5. 权限缓存失效建议加入并发和旧 Token 回归，覆盖角色解绑、用户停用、租户停用三类触发源。
