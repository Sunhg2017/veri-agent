## 1. 准出结论

WP10 当前承诺范围已经形成可验收闭环。`platform-api` 已提供报告控制面、基于 WP9 `REPORT_HANDOFF` 和脱敏 run export 的报告生成/查询/重试/归档、WP9/WP8 aggregate-only evidence manifest、规则失败分类、WP2 受控 AI 诊断、平台内缺陷草稿、JSON/Markdown 脱敏导出摘要、权限、审计、DB validation、诊断质量评测、诊断上下文脱敏专项和 WP10 quality gate；`portal-web` 已提供 `#reports` 工作台，覆盖报告筛选、生成/重试、详情、诊断、草稿、导出、归档、DOM 禁止字段扫描和 390px 响应式 smoke。

当前准出口径不包含 WP3/WP5 evidence adapter、真实 provider 质量评测看板、外部 Jira/禅道/飞书缺陷写入、PDF/Word 完整报告、原始 runner artifact 归档、趋势报表、BI 数仓或生产容量承诺。这些均作为后续专项记录，不构成本轮 WP10 发布阻断。

## 2. 范围和非目标

本次准出范围：

1. WP10 后端控制面：health、report generate/list/detail/retry/archive、evidence manifest、latest diagnosis、AI diagnosis trigger、defect draft create/review、JSON/Markdown export、权限、审计和 traceId。
2. WP10 前端工作台：`#reports` 入口权限、顶部指标、报告筛选、生成报告、重试生成、报告列表、报告详情、失败诊断、缺陷草稿、导出摘要、归档和移动端 smoke。
3. WP10 准出脚本：`scripts/wp10_quality_gate.sh`、report smoke、defect draft smoke、export redaction smoke、diagnosis quality eval、diagnosis redaction eval、frontend Playwright smoke、DB validation 和 Java 行数门禁。
4. WP10 交付文档：启动准备、PRD、技术设计、前端页面设计、前端操作说明、运维 Runbook、测试策略、研发拆解、M1-M8D 交付说明、本发布准出说明和剩余工作盘点。

非目标：

1. 不读取或归档 runner stdout/stderr、请求/响应正文、webhook payload、截图、视频、源码包或 raw prompt/raw response。
2. 不触发 WP9 execution run，不认领队列，不改变执行状态。
3. 不直连 WP8/WP9/WP3/WP5 表；跨 WP 只通过应用服务、导出接口或明确 port 获取 aggregate-only 摘要。
4. 不自动写外部缺陷系统；当前只保存平台内草稿和 masked payload preview。
5. 不导出 PDF/Word 完整报告，不承诺趋势报表、组织 KPI 或 BI 数仓。
6. 不把 AI 诊断作为确定根因；所有 `AI_READY` 均需保留 confidence、evidenceRefs、nextActions 和 `manualReviewRequired`。

## 4. 跳过项和原因

未执行 WP3/WP5 evidence adapter。原因是当前 WP10 P0 已完成 WP9/WP8 evidence manifest 主链路，WP3/WP5 adapter 仍按后续专项推进；不得通过直连表方式临时补齐。

未执行真实 provider 质量评测看板。原因是当前已通过 WP2 受控模型调用和离线诊断质量/脱敏专项覆盖准出主路径；真实 provider 横向质量评测、样本扩展和看板属于后续质量专项。

未执行外部缺陷系统写入。原因是当前缺陷草稿固定为平台内 DRAFT/REVIEWED/DISMISSED 和 masked payload preview，外部 Jira/禅道/飞书写入由后续 WP11 或连接器专项承接。

未执行 PDF/Word 完整报告、原始 artifact 归档、趋势报表或 BI 数仓。原因是当前导出能力以 JSON/Markdown aggregate-only 摘要和 export manifest 收口，完整文件、原始证据和趋势分析均需要独立合规审批与容量设计。

M8C/M8D 是文档-only 收口，不修改 Java、API、DB、脚本或前端运行时代码，因此文档切片不重新执行完整后端/DB/quality gate；目标环境发布仍必须按本说明第 3 节执行 release gate。

## 5. 发布风险

| 风险 | 准出控制 | 处置 |
|---|---|---|
| 报告生成读取未脱敏源数据 | WP9 run export、REPORT_HANDOFF、sourceRunDigest、report smoke 和审计 | 关闭 `WP10_REPORT_GENERATE_ENABLED`，回归 WP9 handoff 和 WP10 report smoke |
| evidence manifest 泄露跨 WP 原文 | summaryKeys/digest/redactionFlags 白名单、M3A/M3B 测试和导出扫描 | 关闭生成和导出，保留 manifestDigest，修复后重跑 redaction smoke |
| AI 诊断输入泄露敏感上下文 | M7B diagnosis redaction eval、contextDigest、rawPromptStored=false/rawResponseStored=false | 关闭 `WP10_DIAGNOSIS_ENABLED`，修复 context builder 后重跑 M7B 专项 |
| AI 诊断误导用户 | `manualReviewRequired=true`、confidence、evidenceRefs、规则 fallback 和前端提示 | 降级到 RULE_READY，要求人工复核 |
| 导出摘要泄露敏感内容 | `REPORT_EXPORT_REDACTION_BLOCKED`、export redaction smoke、DOM smoke | 关闭 `WP10_REPORT_EXPORT_ENABLED`，撤销 `report:export`，修复后重跑 quality gate |
| 缺陷草稿被误认为外部写入 | `externalSystemWriteAttempted=false`、masked payload preview、无发送按钮 | 关闭 `WP10_DEFECT_DRAFT_ENABLED`，保留草稿审计 |
| 前端窄屏或 DOM 脱敏回归 | `wp10_frontend_e2e_smoke.sh` 覆盖桌面/390px 和禁止字段样本 | 暂停发布，修复前端后重跑 smoke/build |
| DB/权限/审计 seed 缺失 | `wp10_reporting_validation.sql`、release role validation 和 DB validation | 阻断发布，按 Flyway 前滚修复 |

## 6. 回滚方式

1. 文档阶段回滚本组 WP10 文档和 README/实现基线索引即可，无运行时影响。
2. 暂停导出：设置 `WP10_REPORT_EXPORT_ENABLED=false`，必要时撤销 `report:export`。
3. 暂停 AI 诊断：设置 `WP10_DIAGNOSIS_ENABLED=false`，保留规则分类 fallback。
4. 暂停缺陷草稿：设置 `WP10_DEFECT_DRAFT_ENABLED=false`。
5. 暂停报告生成和重试：设置 `WP10_REPORT_GENERATE_ENABLED=false`，保留既有报告只读查询。
6. 暂停 WP10 控制面：设置 `WP10_REPORTING_ENABLED=false`。
7. 数据库迁移遵循前滚修复优先，生产环境不做破坏性 drop；已产生的 report、evidence、diagnosis、draft、export manifest 和 audit 证据不得直接删除。
8. 若回退涉及 Java 生产代码，必须重新运行 Java 行数门禁、后端测试和 WP10 quality gate，并记录《阿里巴巴 Java 开发手册》自查结论。
