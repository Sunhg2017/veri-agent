## 1. 测试目标

1. 验证 WP10 只消费 WP9/WP8/WP3/WP5 脱敏摘要，不读取或输出原始敏感产物。
2. 验证报告生成幂等、状态机、快照、schemaVersion、traceId、redaction policy 和可选异步 worker 稳定。
3. 验证规则失败分类在无模型时可用，AI 诊断通过 WP2 策略、预算和脱敏边界。
4. 验证缺陷草稿只保存平台内草稿，不自动写外部缺陷系统。
5. 验证 JSON/Markdown 导出和前端 DOM 不包含禁止字段。
6. 验证终态 webhook 回调默认关闭、按配置签名、aggregate-only payload 和失败不阻断报告链路。
7. 验证权限、项目 scope、审计事件、DB migration 和 quality gate 可作为发布准出入口。

## 4. 安全测试

1. 项目越权读取、生成、诊断、导出和草稿操作必须 403。
2. 报告详情、导出内容、审计 payload、模型输入和前端 DOM 不包含 secret、token、cookie、Authorization、password、lease token、`secret://` 原文或完整 secretRef。
3. 不包含 runner stdout/stderr、请求正文、响应正文、webhook payload、截图、视频、源码包、raw prompt、raw response 或 provider error 原文。
4. AI 诊断上下文超过上限时必须裁剪，并输出 contextDigest 和 truncation flag。
5. 脱敏扫描命中禁止字段时，导出状态为 BLOCKED，不返回命中敏感值本身。
6. 缺陷草稿 payload preview 默认 masked，不包含外部系统 token 或真实 webhook 地址。
7. webhook 回调 body 不包含 raw evidence、failureSummary、request/response body、raw prompt/raw response 或 secret 明文。

## 6. 建议脚本入口

代码阶段新增：

```bash

bash scripts/wp10_export_redaction_smoke.sh
bash scripts/wp10_diagnosis_quality_eval.sh
bash scripts/wp10_diagnosis_redaction_eval.sh
bash scripts/wp10_quality_gate.sh
```

`wp10_quality_gate.sh` 应串联：

1. 脚本语法检查。
2. `bash scripts/platform_api_java_line_guard.sh`。
3. 后端 WP10 service/controller/OpenAPI/permission/audit 测试。
4. `ReportGenerationWorkerServiceTest`、`ReportingHealthControllerTest`、`ReportingWebhookDispatcherTest` 和 JDBC repository contract 覆盖 worker 状态机、health 字段、终态回调和 DB 条件认领。
5. `mvn -B -pl platform-api test` 或定向 WP10 测试加必要跨 WP contract 测试。
6. 前端 WP10 Vitest。
7. `cd portal-web && npm run build`。
8. `bash db/validation/run_wp1_db_validation.sh`。
9. `wp10_report_smoke.sh`，开发模式可 mock 或 managed，release 模式必须 managed。
10. `wp10_export_redaction_smoke.sh`，当前扫描服务端 report detail/export 禁止字段。
11. `wp10_frontend_e2e_smoke.sh`，覆盖桌面/390px 工作台主链路、DOM 禁止字段样本扫描和无横向溢出。
12. `wp10_diagnosis_quality_eval.sh`，离线覆盖 timeout、dependency blocked、runner disabled、账号锁定和 webhook 幂等冲突。
13. `wp10_diagnosis_redaction_eval.sh`，离线构造危险 report summary、evidence manifest 和 rule diagnosis，扫描 WP2 bounded context 禁止字段和值。

## 7. 诊断质量评测

M7A 已新增 `scripts/wp10_diagnosis_quality_eval.sh` 和 `RuleFailureClassifierQualityEvaluationTest`。当前评测直接使用 aggregate-only evidence manifest 调用规则分类器，覆盖 `TIMEOUT`、`DEPENDENCY_BLOCKED`、`RUNNER_FAILURE`、`TEST_DATA_ACCOUNT` 和 webhook 幂等冲突 `UNKNOWN` fallback；该脚本已纳入 `scripts/wp10_quality_gate.sh`，可通过 `WP10_SKIP_DIAGNOSIS_EVAL=1` 显式跳过并在准出说明记录风险。

M7B 已新增 `scripts/wp10_diagnosis_redaction_eval.sh` 和 `ReportDiagnosisContextRedactionEvaluationTest`。当前评测直接构造含危险 key 和危险文本的 report summary、evidence manifest、rule diagnosis，验证 `ReportDiagnosisContextBuilder` 在发送 WP2 前过滤 raw prompt、raw response、runner stdout/stderr、request/response body、webhook payload、secretRef、Authorization、Bearer 和 lease token 等样本；安全策略字段如 `rawPromptIncluded=false` 允许保留。该脚本已纳入 `scripts/wp10_quality_gate.sh`，可通过 `WP10_SKIP_DIAGNOSIS_REDACTION_EVAL=1` 显式跳过并在准出说明记录风险。

| 维度 | P0 阈值建议 |
|---|---|
| 分类命中率 | 离线样例 primary category 命中率不低于 80%。 |
| 安全率 | 诊断输出和上下文禁止字段命中为 0。 |
| 上下文脱敏率 | WP2 bounded context 中危险 key、危险值和原始产物标记命中为 0。 |
| 人工确认 | AI_READY 结果 `manualReviewRequired` 覆盖率 100%。 |
| 证据引用 | 每个候选根因至少包含一个 evidenceRef 或明确说明无证据。 |
| 降级可用 | WP2 不可用时规则分类仍通过主路径测试。 |

## 8. DB Validation

WP10 涉及数据库、权限、审计和模型调用，必须参考 `doc/mvp/final/engineering/WP1-WP4-统一发布准出清单.md`。DB validation 需要覆盖：

1. `report_execution_report`、`report_evidence_manifest`、`report_failure_diagnosis`、`report_defect_draft`、`report_export_manifest` 表存在。
2. 唯一约束、状态 check、外键、索引和时间字段存在。
3. `report:read/generate/diagnose/export/manage` 权限 seed 存在。
4. 默认角色映射符合 PRD。
5. 审计事件字典包含 WP10 事件。
6. schema 中不存在 `tenant_id` 回归。

## 9. 准出标准

1. 报告生成、详情、诊断、草稿和导出主链路可在前端完成。
2. 权限、项目 scope、审计、traceId、schemaVersion 和 redactionPolicy 覆盖主链路。
3. WP9/WP8/WP3/WP5 adapter 不直连跨 WP 表，不读取敏感原文。
4. AI 诊断输入输出均通过脱敏扫描，fallback 可用。
5. 缺陷草稿不写外部系统，payload preview masked。
6. 后端、前端、构建、DB validation、report smoke、redaction smoke、diagnosis eval、diagnosis redaction eval 和 WP10 quality gate 按影响面通过。
