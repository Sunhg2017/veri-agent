## 1. 需求结论

本轮 WP10 推进完成 M2A 后端切片：`platform-api` 新增报告生成、分页查询、详情、重试和归档接口，报告快照只保存 aggregate-only summary、redaction policy、source run digest、traceId 和状态信息。

本轮不实现 M3 证据 manifest 聚合、M4 规则/AI 失败诊断、M5 缺陷草稿和 JSON/Markdown 导出，也不改 `portal-web` 报告工作台。这些继续按 WP10-3.x 到 WP10-6.x 推进。

## 3. 验收标准

1. `POST /api/v1/reports` 可基于 WP9 脱敏 run export 生成 READY 报告，重复 `projectId + executionRunId + requestKey` 返回同一 report 且 `idempotentReplay=true`。
2. 生成前先校验 WP9 run 项目归属；跨项目 run 返回 `REPORT_SOURCE_RUN_NOT_FOUND`，不调用 WP9 export。
3. 源 run 未终态或缺少 READY `REPORT_HANDOFF` 摘要时返回 `REPORT_SOURCE_RUN_NOT_READY`。
4. `GET /api/v1/reports`、`GET /api/v1/reports/{id}` 按项目 scope 校验 `report:read`。
5. `POST /api/v1/reports/{id}/archive` 按项目 scope 校验 `report:manage`，状态收敛为 `ARCHIVED`。
6. 报告响应、持久化 summary 和 redaction policy 不包含 secret、token、cookie、Authorization、lease token、raw prompt、raw response、runner stdout/stderr、请求响应正文或 webhook payload。

本轮涉及数据库、权限、跨 WP 和发布准出边界，需参考 `doc/mvp/final/engineering/WP1-WP4-统一发布准出清单.md` 并执行与影响面匹配的最小必要验证。

## 5. 风险与回滚

| 风险 | 处置 | 回滚 |
|---|---|---|
| WP9 export 契约变化 | M2 只消费 `ExecutionRunExportResponse` 白名单字段，digest 覆盖 schema/run/counts/policy | 回退本次 commit 或临时关闭 `veri-agent.reporting.generate-enabled` |
| 报告误含未脱敏数据 | 仅从 WP9 export 读取，redaction policy 标记 aggregate-only，测试断言敏感字段不出现在响应 | 删除生成报告记录并回退本次 commit |
| 后续 M3-M5 数据被误认为已完成 | 详情返回空 evidence、`NOT_REQUESTED` diagnosis 和空草稿，文档明确未完成 | 保持 M2 接口，只隐藏前端后续入口 |
