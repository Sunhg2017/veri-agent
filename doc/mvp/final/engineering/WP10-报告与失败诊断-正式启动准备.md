# WP10 报告与失败诊断 - 正式启动准备

| 项目 | 内容 |
|---|---|
| 工作包 | WP10 报告与失败诊断 |
| 角色产出 | 资深项目经理 |
| 文档性质 | 正式启动前范围冻结、里程碑、风险和准入清单 |

## 1. 启动结论

WP10 可以进入正式研发准备完成状态。当前启动包冻结目标、范围、非目标、跨 WP 依赖、里程碑、风险、验收标准和回滚方式；本轮只完成前期准备和任务拆解，不引入运行时代码、数据库迁移或前端页面变更。

WP10 的核心目标是把 WP9 已经提供的执行摘要和 `REPORT_HANDOFF` 状态，组织成可审计、可脱敏、可追踪的测试报告和失败诊断控制面。首期聚焦报告生成、证据聚合、失败分类、AI 诊断建议和缺陷草稿，不建设外部缺陷系统写入、不读取未脱敏 runner 原始日志、不生成不可追溯的自由文本报告。

## 2. 目标

1. 基于 WP9 `GET /api/v1/execution/runs/{id}/export` 生成版本化报告快照，保留 run/node 状态计数、错误摘要、traceId 和 redaction policy。
2. 汇总 WP8 数据准备、账号租借、释放和清理任务证据摘要，作为报告的环境和数据上下文。
3. 关联 WP3 需求、用例、API、页面、业务流和追踪关系摘要，形成需求到执行结果的闭环。
4. 使用 WP2 模型接入层生成失败诊断建议、可能根因、下一步排查动作和缺陷草稿摘要；模型输入必须是脱敏、裁剪、可审计上下文。
5. 在 `portal-web` 提供报告列表、报告详情、失败诊断、证据摘要、缺陷草稿和脱敏导出入口。
6. 建立 WP10 后端、前端、DB validation、AI 诊断质量评测和 release quality gate 验证入口。

## 3. 范围

| 范围项 | 说明 |
|---|---|
| 报告快照 | 从 WP9 run export 和 report handoff 创建 `executionReport`，固化 schema version、run summary、node status counts、redaction policy 和生成状态。 |
| 证据聚合 | 读取 WP8/WP9/WP3/WP5 已脱敏摘要，形成 evidence manifest；不直连跨 WP 表，不复制敏感原文。 |
| 失败分类 | 按状态、errorCode、runnerMode、dependency blocked、timeout、账号租借释放状态、trigger 来源等维度聚合失败原因。 |
| AI 失败诊断 | 通过 WP2 模型调用生成 bounded 诊断摘要，输出置信度、依据摘要、建议动作和需要人工确认的风险。 |
| 缺陷草稿 | 生成缺陷标题、复现摘要、影响范围、证据引用和优先级建议；P0 只保存草稿，不写外部缺陷系统。 |
| 导出摘要 | 提供脱敏 JSON/Markdown 摘要和导出 manifest；不导出 runner 原始 stdout/stderr、请求响应正文、secret、账号凭据或 webhook payload。 |
| 权限审计 | 新增 `report:read/generate/diagnose/export/manage` 权限和报告生成、诊断、导出、缺陷草稿审计。 |
| 前端 | 新增 `#reports` 工作台，覆盖报告列表、生成状态、诊断详情、证据摘要、缺陷草稿和导出。 |
| 质量门禁 | 后端、前端、DB validation、脱敏安全扫描、AI 诊断评测、Playwright smoke 和 WP10 quality gate。 |

## 4. 非目标

| 非目标 | 说明 | 后续承接 |
|---|---|---|
| 读取 runner 原始产物 | WP10 P0 只消费 WP9/WP6/WP8 已脱敏摘要，不读取原始日志、请求响应、截图、视频或源码。 | 受控 artifact 专项 |
| 重新执行测试或调度任务 | WP10 不触发 runner、不认领队列、不改变执行状态。 | WP9/WP6/WP7 |
| 自动写入 Jira/禅道/飞书缺陷 | P0 只生成缺陷草稿和外部系统 payload preview。 | WP11 企业连接器 |
| 替代 WP5 测试设计报告 | WP10 聚焦执行报告和失败诊断，不生成用例生成质量报告。 | WP5 |
| 导出包含敏感明细的完整报告文件 | P0 只输出脱敏摘要和 manifest，不导出行级敏感 evidence。 | 合规审批专项 |
| 生产容量承诺和 BI 数仓 | 不建设长周期数据仓库、趋势报表或组织级 KPI 平台。 | 后续分析平台 |

## 9. 风险和回滚

| 风险 | 处置 | 回滚方式 |
|---|---|---|
| 报告泄露敏感字段 | 响应白名单、导出安全扫描、前端 DOM 扫描和 redaction policy 固化 | 关闭 report export，回滚导出接口，轮换受影响 secret |
| 诊断误导用户 | 输出置信度、依据摘要和人工确认标记；保留模型调用 trace 和 fallback | 关闭 AI diagnosis，保留规则分类 |
| 跨 WP 数据不一致 | 报告使用快照和 digest，保留 source schemaVersion 和 generatedAt | 重新生成报告快照，不修改源 run |
| 与 WP9 职责混淆 | WP10 只消费 run export，不改变 execution 状态 | 隐藏报告生成入口，保留 WP9 run export |
| 外部缺陷系统误写 | P0 不写外部系统，只生成草稿和 payload preview | 禁用 defect draft export |
| 报告任务堆积 | M1-M2 先提供手动生成和幂等，后续再加异步队列限流 | 暂停生成入口，保留只读查询 |

## 10. 回滚方式

1. 文档阶段回滚本组 WP10 文档和 README 索引即可，无运行时影响。
2. 后续代码阶段优先通过配置关闭 `veri-agent.reporting.enabled`、`diagnosis-enabled` 或 `export-enabled`。
3. 数据库迁移遵循前滚修复优先，生产环境不做破坏性 drop。
4. 已产生的报告、诊断和导出审计保留，不直接删除证据。
5. 若 WP2 模型诊断异常，关闭 AI 诊断入口并回退到规则分类，不影响报告快照查询。

## 11. 验收标准

1. 本轮新增 WP10 启动准备和研发任务拆解，范围、非目标、依赖、风险、验收和回滚清晰。
2. README 索引能定位 WP10 文档。
3. 明确 PRD、技术设计、前端页面设计、测试策略仍是 M0 后续启动包任务，未误认为代码开发已可直接开始。
4. 本轮不引入业务代码、数据库迁移或运行时配置变更。
5. 文档引用检查和 `git diff --check` 通过并提交推送。
