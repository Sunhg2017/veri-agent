## 1. 启动结论

WP10 已完成当前承诺范围的分阶段研发和文档收口。当前启动包最初冻结目标、范围、非目标、跨 WP 依赖、里程碑、风险、验收标准和回滚方式；截至 M12，PRD、技术设计、前端页面设计、测试策略、研发拆解、前端操作说明、运维 Runbook、发布准出说明、剩余工作盘点、本地准出执行记录、WP3/WP5 evidence adapter 交付说明、异步生成 worker 交付说明、平台级真实文件下载与对象存储化专题交付说明和 PDF/Word 完整报告交付说明均已补齐。

WP10 的核心目标是把 WP9 已经提供的执行摘要和 `REPORT_HANDOFF` 状态，组织成可审计、可脱敏、可追踪的测试报告和失败诊断控制面。首期聚焦报告生成、证据聚合、失败分类、AI 诊断建议和缺陷草稿，不建设外部缺陷系统写入、不读取未脱敏 runner 原始日志、不生成不可追溯的自由文本报告。

当前完成口径：WP10 已支持 health、report generate/list/detail/retry/archive、可选异步入队、后台生成 worker、stale `GENERATING` 恢复、WP9/WP8/WP3/WP5 aggregate-only evidence manifest、`RULE_READY` 规则分类、WP2 受控 AI 诊断、平台内缺陷草稿、JSON/Markdown/PDF/Word 脱敏导出、真实文件下载、`#reports` 前端主链路、前端浏览器 smoke、诊断质量评测、诊断上下文脱敏评测、WP10 quality gate、本地 release gate 执行记录和文档准出。当前 WP10 范围无剩余 P0 功能开发项；后续专项见 `WP10-报告与失败诊断-剩余工作盘点.md`。

## 2. 目标

1. 基于 WP9 `GET /api/v1/execution/runs/{id}/export` 生成版本化报告快照，保留 run/node 状态计数、错误摘要、traceId 和 redaction policy。
2. 汇总 WP8 数据准备、账号租借、释放和清理任务证据摘要，作为报告的环境和数据上下文。
3. 关联 WP3 需求、用例、API、页面、业务流和追踪关系摘要，形成需求到执行结果的闭环。
4. 使用 WP2 模型接入层生成失败诊断建议、可能根因、下一步排查动作和缺陷草稿摘要；模型输入必须是脱敏、裁剪、可审计上下文。
5. 在 `portal-web` 提供报告列表、报告详情、失败诊断、证据摘要、缺陷草稿和脱敏导出入口。
6. 建立 WP10 后端、前端、DB validation、AI 诊断质量评测和 release quality gate 验证入口。

| 前端 | 新增 `#reports` 工作台，覆盖报告列表、生成状态、诊断详情、证据摘要、缺陷草稿和导出。 |

## 4. 非目标

| 非目标 | 说明 | 后续承接 |
|---|---|---|
| 读取 runner 原始产物 | WP10 P0 只消费 WP9/WP6/WP8 已脱敏摘要，不读取原始日志、请求响应、截图、视频或源码。 | 受控 artifact 专项 |
| 重新执行测试或调度任务 | WP10 不触发 runner、不认领 WP9 execution 队列、不改变执行状态；仅认领 WP10 自己的报告生成队列。 | WP9/WP6/WP7 |

## 9. 风险和回滚

| 风险 | 处置 | 回滚方式 |
|---|---|---|
| 报告泄露敏感字段 | 响应白名单、导出安全扫描、前端 DOM 扫描和 redaction policy 固化 | 关闭 report export，回滚导出接口，轮换受影响 secret |
| 诊断误导用户 | 输出置信度、依据摘要和人工确认标记；保留模型调用 trace 和 fallback | 关闭 AI diagnosis，保留规则分类 |
| 跨 WP 数据不一致 | 报告使用快照和 digest，保留 source schemaVersion 和 generatedAt | 重新生成报告快照，不修改源 run |
| 与 WP9 职责混淆 | WP10 只消费 run export，不改变 execution 状态 | 隐藏报告生成入口，保留 WP9 run export |
| 外部缺陷系统误写 | P0 不写外部系统，只生成草稿和 payload preview | 禁用 defect draft export |
| 报告任务堆积 | 通过 `veri-agent.reporting.generation-worker-*` 控制后台 worker 批量、间隔和 stale 恢复；必要时关闭异步入队或生成入口 | 暂停生成入口，保留只读查询 |

## 10. 回滚方式

1. 文档阶段回滚本组 WP10 文档和 README 索引即可，无运行时影响。
2. 后续代码阶段优先通过配置关闭 `veri-agent.reporting.enabled`、`diagnosis-enabled` 或 `export-enabled`。
3. 数据库迁移遵循前滚修复优先，生产环境不做破坏性 drop。
4. 已产生的报告、诊断和导出审计保留，不直接删除证据。
5. 若 WP2 模型诊断异常，关闭 AI 诊断入口并回退到规则分类，不影响报告快照查询。

## 11. 验收标准

1. 当前 WP10 范围、非目标、依赖、风险、验收、回滚和后续专项边界清晰。

4. M10 worker 不引入数据库迁移或前端页面变更。
5. 文档引用检查和 `git diff --check` 通过并提交推送。
