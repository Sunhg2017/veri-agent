# WP6 OpenAPI 接口自动化 - 正式启动准备

| 项目 | 内容 |
|---|---|
| 工作包 | WP6 OpenAPI 接口自动化 |
| 角色产出 | 资深项目经理 |
| 文档性质 | 正式启动前范围冻结、里程碑、风险和准入清单 |
| 当前口径 | 单个 `platform-api` Java 服务承载 WP6 控制面；Pytest 执行器通过受控 runner 契约接入；WP6 不承接 WP9 调度和 WP10 完整报告诊断 |
| 版本 | v0.1 |
| 日期 | 2026-06-11 |

## 1. 启动结论

WP6 可以进入正式研发准备完成状态。当前启动包已冻结 P0 范围、非目标、跨 WP 依赖、接口契约、前端入口、测试策略、风险和回滚方式。

正式编码前仍需项目提供至少 1 份真实但脱敏的 OpenAPI 样本，以及可用于本地 smoke 的测试服务 baseUrl；没有真实样本时，可以先使用仓库 fixture 完成解析、生成、权限、审计和前端主链路。

## 2. 目标

WP6 的目标是跑通“OpenAPI 规格导入 -> 接口资产对齐 -> 接口自动化用例生成 -> Pytest 脚本包产出 -> 受控试运行 -> 结果采集”的最小闭环，为 WP9 调度和 WP10 诊断报告提供可执行输入。

## 3. 范围

| 范围项 | 说明 |
|---|---|
| OpenAPI 导入 | 支持 OpenAPI 3.x JSON/YAML 上传、URL 拉取和文本粘贴；解析 service、path、method、operationId、参数、请求体、响应码和 schema 摘要。 |
| 接口资产对齐 | 与 WP3 `asset_api` 做 preview/diff/sync，不直接越过 WP3 应用服务写资产表。 |
| 自动化用例生成 | 基于 OpenAPI、WP3 API 资产、WP5 已确认测试用例和可选 WP2 Prompt 生成接口用例草稿。 |
| 脚本包管理 | 产出 Pytest 风格脚本包、依赖清单和静态校验摘要；脚本正文默认由平台托管，不直接暴露密钥或环境变量。 |
| 受控试运行 | 支持单次手动触发 smoke/run，限制超时、并发、目标 baseUrl 和网络访问；不做定时调度。 |
| 结果采集 | 采集用例级 pass/fail/skip/error、耗时、断言摘要、脱敏错误和产物引用。 |
| 权限审计 | 所有导入、生成、执行、导出动作按项目 scope 鉴权并写审计。 |

## 4. 非目标

| 非目标 | 说明 | 后续承接 |
|---|---|---|
| UI/E2E 脚本生成 | Playwright、截图、视频和页面行为稳定性由 WP7 承接。 | WP7 |
| 执行计划和定时调度 | WP6 只支持手动单次试运行，不做 DAG、定时、CI 回调和 worker 池调度。 | WP9 |
| Allure 风格完整报告与 AI 诊断 | WP6 只提供运行结果摘要和脱敏失败信息。 | WP10 |
| 测试数据与账号池 | 仅引用环境变量和 secretRef，不建设数据构造、账号租借和清理。 | WP8 |
| 生产压测或破坏性测试 | 不生成高并发、写入破坏性或越权攻击脚本。 | 专项安全/性能工作 |
| 直连模型厂商 | 所有 AI 生成必须通过 WP2 模型接入层。 | 不适用 |

## 5. 涉及模块

| 模块 | 影响 |
|---|---|
| `platform-api` | 新增 `apiautomation` 领域模块，承载 OpenAPI 源、导入任务、生成任务、脚本包、运行任务和结果摘要。 |
| WP1 平台基础 | 复用项目/环境、RBAC、审计、traceId、SecretProvider 和资源 scope。 |
| WP2 模型接入 | 使用 Prompt 生成断言、参数组合和边界场景；预算、脱敏、调用日志由 WP2 控制。 |
| WP3 资产管理 | 读取/同步 API 资产，建立 API 与自动化用例/脚本包追踪关系。 |
| WP5 用例生成 | 读取已确认测试用例和覆盖策略，作为接口自动化用例生成输入；不反向修改 WP5 候选。 |
| `portal-web` | 新增“接口自动化”工作台，覆盖导入、diff、生成、脚本包、试运行和结果摘要。 |
| `db/migration/wp1` | 后续新增 WP6 表、权限、索引、注释和 validation。 |
| `scripts` | 后续新增 `scripts/wp6_quality_gate.sh`、OpenAPI fixture smoke 和 runner smoke。 |

## 9. 风险和回滚

| 风险 | 处置 | 回滚方式 |
|---|---|---|
| OpenAPI 样本不规范导致解析范围膨胀 | P0 只支持 OpenAPI 3.x 常见 schema，复杂 oneOf/allOf 先降级为摘要 | 关闭导入任务或回滚导入记录，不影响 WP3 既有资产 |
| 模型生成脚本不稳定 | 默认提供确定性模板 fallback，模型输出必须结构校验 | 关闭 WP2 生成开关，保留手动脚本草稿 |
| 执行器误访问非目标地址 | baseUrl allowlist、超时、并发和网络策略默认收紧 | 禁用执行入口，保留导入和生成能力 |
| 结果泄露敏感信息 | 白名单字段入库，错误和请求响应只存脱敏摘要 | 删除运行产物引用，保留聚合结果和审计 |
| 与 WP9/WP10 范围冲突 | WP6 只做手动单次运行和摘要，调度/完整报告留后续 | 从菜单隐藏执行入口，不影响导入/生成 |

## 10. 验收标准

1. 五角色文档均完成且口径一致。
2. P0 范围、非目标、依赖、权限、审计、安全和回滚已明确。
3. 后续开发可以直接按接口契约拆分 DB、后端、前端、测试任务。
4. 没有提前引入业务代码、数据库迁移或未验证执行器行为。
5. 文档变更通过格式检查并提交推送。
